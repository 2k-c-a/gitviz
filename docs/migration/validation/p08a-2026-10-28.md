## 구현

| 영역 | 내용 |
|---|---|
| 데이터(schema 7) | `workspace_event`(불변 trigger, 전역 `sequence`, UNIQUE(project, source_type, source_id, source_revision, type)), `notification`(UNIQUE(project, dedupe_key), count, read_at, version). `local_project` FK는 cascade가 아니다 |
| 기록 시점 | review 종료(성공·실패·취소·결과 불명, 재시작 복구 포함), validation 종료(중단 포함), proposal의 applied·recovery_required·restored. 모두 상태 변경과 **같은 transaction** 안에서 기록하며, transaction 밖 호출은 거부한다 |
| 내용 | ID·유형·심각도·원인 코드·요약 수치(지적 수, 최고 심각도, 종료 코드)만 저장한다. 소스·경로·프롬프트·출력은 저장하지 않는다. AI 추론(`ai-findings`)과 결정적 명령 실패(`command-nonzero-exit`)는 원인 코드로 구분한다 |
| 중복 | 같은 사건이 다시 기록되면 새 알림을 만들지 않고 count, lastSeen, version만 올린다 |
| RPC | `workspace.notifications.list`(필터와 묶인 cursor, 최대 100건), `workspace.notifications.markRead`(projectId 필수, version CAS, idempotency), `workspace.events.read`(sequence 이후 catch-up, reset·hasMore 표시) |
| main | `EventRelay`가 workspace 문서에만 2초 주기로 "갱신하라" 신호를 보낸다. 신호에는 본문이 없다. 구독 시작은 현재 시점부터이며, 신호에 빈 번호가 생기면 resync를 보낸다 |
| UI | `inbox.js`: 프로젝트·종류·심각도·읽음 필터, 텍스트로만 렌더링, 읽음 전환. `navigation.js`: 대상 프로젝트를 고른 뒤 agent의 기존 get API로 FK를 다시 검증하고 이동만 한다 |

## 승인 목록 밖 수정(보고 대상)

연결과 기존 테스트 기대값을 맞추는 데 필요한 수정이다. 동작 정책은 바꾸지 않았다.

- `desktop/src/app-protocol.ts`: 앱 자산 허용 목록에 `inbox.js`, `navigation.js` 추가
- `desktop/scripts/build.mjs`: 빌드 복사 목록에 두 파일 추가
- `desktop/src/contracts.ts`: 새 연산의 결과 스키마 매핑
- `desktop/src/main.ts`: `registerNotifications` 등록
- `desktop/src/agent.ts`: handshake 스키마 범위 7, appVersion 0.8.0
- 응답 스키마 handshake `capabilities.maxItems` 44→47. 이 상한 때문에 desktop이 handshake를 거부해 e2e가 일괄 실패했고, 수정했다
- 기존 테스트의 schema 버전과 테이블 목록 기대값을 7로 갱신: `test_dispatcher`, `test_projects`, `test_recovery`, `test_review`, `test_snapshots`, `test_p06_migration`, `test_p07_migration`, `agent.test.ts`, `bridge-security.test.ts`, `foundation.e2e.ts`의 preload 허용 목록. 테스트를 약화하지 않았다. 지원하지 않는 범위 테스트는 7~8에서 8~9로 옮겼다

## 설계와의 차이

- 07의 `workspace.events.subscribe/unsubscribe`는 agent RPC가 아니라 main↔renderer IPC(`workspace:events-subscribe/unsubscribe`, push 채널 `workspace:event`)로 구현했다. agent는 요청-응답만 하므로 catch-up 조회 `workspace.events.read`를 새로 두었다. 08 문서의 "preload: event 해제 함수" 책임과 같은 구조다.
- 06의 notification 열에 `created_at`을 추가하고, 심각도는 event에 둔다. 정렬과 cursor는 created_at+id 내림차순이다.
- 원격 분석 완료 감지, `projects.connectRemote`, navbar·page-context 연결은 P08b 범위로 미착수다.

## Hyper-V 시도 기록

`.validation\p08-vm`에 개발 VM `GitViz-P08-Dev-Win11`을 P01 base의 차등 디스크로 만들었다.

- P01 base에는 부팅 설정이 없었고, 설치 도중 강제 전원 차단까지 겹쳐 첫 VM이 손상됐다.
- 다시 만든 VM은 P01Admin 세션까지 기동했지만, 사용자 지시로 호스트 실행으로 바꾸며 중단했다.
- 이 VM은 개발 도구가 들어간 비격리 검증용이며, P01 clean VM 인수를 대체하지 않는다. VM 안 레지스트리에 테스트 계정 비밀번호가 남아 있으므로 필요 없으면 삭제를 권장한다.
- 기존 P01 clean VM과 그 디스크는 바꾸지 않았다.
