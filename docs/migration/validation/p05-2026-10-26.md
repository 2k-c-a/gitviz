## 정책·구현 범위

사용자는 Q04에 대해 기본 보안 정책으로 구현하도록 확인했다. 현재 local_project의 remoteRepositoryId는 항상 null이고 인증된 공개 매핑 proof 계약이 없으므로 **현재 모든 cloud 실행은 CLOUD_MAPPING_REQUIRED로 차단**한다. Git remote URL이나 renderer visibility를 공개 확인으로 취급하지 않는다. 공개 mapped cloud BYOK 활성화에는 서버의 공개 매핑 검증·PC credential 등록/버전·cloud adapter 통합이 추가로 필요하며 구현 완료로 집계하지 않는다.

PC 경로는 기존 불변 ollama-local-v1(qwen2.5-coder:7b, 고정 127.0.0.1:11434)을 우선 연결한다. 모델 tag의 실제 weight digest 고정·다른 PC runtime 지원·모델 품질은 미검증이다. 원격 서버의 local 모델과 혼동하지 않도록 executionLocation=user-pc를 표시한다. PC 모델 provider 요금 예약/추정은 USD 0, uncertain ledger는 해제하지 않으며 OS 자원 비용 무료를 뜻하지 않는다. 새 의존성은 추가하지 않았다.

preview는 실제 system/user 문자열·선택 diff 문맥·제외·coverage·목적·profile/policy/input/manifest hash를 보여주며 5분 메모리 ticket(최대32개)에 묶는다. start는 일치 hash·명시 동의·동일 project를 다시 확인한다. job/동의/비용 예약/operation은 같은 transaction으로 접수하고 transport 전 running/attempt intent를 기록한다. 동일 fingerprint/generation은 다른 operation key로도 새 호출하지 않는다. 다음 generation은 명시 중복 위험 확인을 요구한다. transport worker는 SQL에 접근하지 않으며 완료·취소·재시작 결과를 단일 writer가 확정한다. 응답 불명은 uncertain·자동 재송신 없음이다.

새 severity schema는 기존 priority를 변환하지 않는다. 엄격 구조와 전송한 fileId/facet/path/side/줄/정확한 quote를 검사하고 하나라도 어긋나면 결과 전체를 실패 처리한다. 원본 사람 판정은 unverified로 고정하며 별도 암호화 feedback/CAS를 저장한다. 리뷰 자료가 남은 프로젝트 등록 해제는 현재 보존정책 결정 전 차단한다(원본 삭제 없음). refactor 생성은 P06 prompt/schema 단계에 남긴다.

## 검증 상태

- strict TS/Pyright, ESLint, Ruff 및 renderer 자산 build 통과. 이 build는 TypeScript/자산 생성이다. 후속 별도 승인으로 agent freeze·검증 패키징도 통과했다.
- DB·네트워크 없는 순수 출력/loopback transport mock 4개 통과(아래 최종60개에 포함). URL 위조·redirect·잘못된 evidence/severity/검증 주장·중복 JSON key·출력 크기 제한을 확인했다.
- host 18개 최초 실행에서 sandbox의 SecretStore 파일 게시 검사 2개가 STORAGE_UNAVAILABLE로 실패했다. 표준 사용자 환경 재실행에서 18개 모두 통과했다.
- 임시 schema1/2/3→4 migration·backup·중간 실패 rollback을 포함한 전체 workspace 60개와 실제 Electron source agent/fake provider가 별도 승인 후 통과했다. 실제 모델·서버 DB 연결·사용자 DB migration은 미실행이다. fake loopback provider와 freeze·package는 별도 승인 후 통과했다.

중간 정적 검사에서 새 테스트의 Any 경계와 semicolon 형식을 수정했으며 주석 분리 중 생긴 syntax 오류도 수정 후 재검사했다. 통과하지 않은 실행을 성공 집계하지 않는다. 작성 당시에는 미완료였으며, 아래 최종 상태가 현재 판단 기준이다.

## Frozen agent·독립 패키지 최종 인수

사용자가 P05 격리 재빌드·기존 실제 Electron 회귀·독립 검증 패키징을 추가 승인했다. `python -X utf8 -B scripts/build_workspace_agent.py`, `GITVIZ_VERIFY_P05=1 npm run package`, `scripts/validate_p05_package.ps1`이 각각 exit0으로 완료됐다. P04 검증 패키지의 EXE·ASAR·agent를 기존 P04 인수 hash와 대조해 세 값 모두 보존됨을 확인했다. installer·서명·배포는 수행하지 않았다.

새 frozen agent로 review-preview·changes·foundation·projects·auth·remote-compat의 실제 Electron 6개 시나리오가 모두 exit0/PASS였다. 기존 프로젝트·DPAPI 재시작·CSP/sender·원격 화면/인증 fixture 및 원본/index 보존을 포함한다. 최종 로그는 `.validation/p05/final-frozen-*.{stdout,stderr}.log`다. 원격 검사는 기존 HTTP fixture이며 P03 실제 OAuth를 대체하지 않는다.

P05 시나리오는 테스트 main이 127.0.0.1:11434를 먼저 점유한 경우에만 리뷰를 시작한다. 이미 실제 runtime이 사용하는 포트라면 시작 전에 실패하며 그 runtime에 요청하지 않는다. 테스트가 소유한 fake HTTP provider에서 실제 전송 본문 SHA256=동의 preview의 requestHash, 새 context/output schema, 결과 검증·저장과 unverified 표시를 확인했다. 다음 실행 세대를 명시 승인하고 요청 수신 후 fixture agent 프로세스만 강제 종료했다. 같은 임시 DB/DPAPI key로 새 agent를 시작해 uncertain·attempt1·예약 유지 및 추가 송신 0건을 확인했다. 가짜 응답은 모델 품질 검증이 아니다.

독립 `GitVizWorkspaceP05Verify-win32-x64` 패키지도 표준 사용자·PATH=System32에서 동일한 fake-provider/강제 종료 복구 시나리오를 통과했다. 포함 agent hash가 최종 dist agent와 일치했다. 설치된 Git과 Node 경로 조회를 사용한 **개발 호스트 인수**이며 새 clean VM으로 집계하지 않는다. 실제 모델 호출은0건이다.
