## 승인·선행 gate

2026-10-25 사용자는 **P03의 실제 서버 OAuth·웹/앱 동시 사용 인수가 남아 있음을 명시하고 P04를 진행**하도록 승인했다. P03 전체 완료로 처리하지 않는다. 이 실환경 gate는 후속 통합/출시 인수에서 별도 확인한다. P04 선행인 P02는 검증 완료 상태다.

Q06의 우선 manifest 탐지 범위는 JS/TS와 Python으로 승인했다. 다른 언어는 근거와 미지원 상태를 표시하며 최종 parser/도구 지원표를 확정한 것으로 확대하지 않는다. 기존 AI DTO/policy/validator 재사용을 위해 Pydantic2.13.4와 전이 pydantic-core2.46.4·annotated-types0.7.0·typing-inspection0.4.2를 workspace 격리 환경에 추가하도록 별도 승인했다. 기존 typing-extensions4.16.0과 서버 venv는 유지한다.

## 현재 변경과 실행 결과

추가 파일은 snapshots/detection·adapters/ai_core, shared RPC schema/fixture 확장, changes UI, snapshot/detection/core/Windows Git fixture 및 실제 Electron `desktop/tests/changes.e2e.ts`다. 기존 projects의 grant/멱등 transaction seam, dispatcher, agent/main/preload·자산 빌드와 기존 foundation 기대값을 schema3·추가4개 capability에 맞췄다. app version은0.4.0이며 npm 의존성 버전 변경은 없다.

기존 서버 수정은 input_builder의 profile 주입/서버 error 변환 lazy import 및 registry의 환경 주입/서버 설정 lazy import에 한정한다. 기본 server 호출과 profile/prompt/DTO 값은 유지하며 validators 자체는 수정하지 않았다. agent freeze 설정은 재사용하는 순수 AI module/고정 prompt만 포함하고 DB·웹·수집 clone·HTTP provider 구현은 제외하도록 작성했다. freeze 모듈 목록 599개를 검사해 해당 금지 모듈이 포함되지 않음을 확인했다. 이는 모든 네트워크 접근을 OS 수준에서 차단했다는 의미는 아니다.

- 격리 wheel4개를 hash lock으로 설치했고 `pip check`가 통과했다. 서버 venv/requirements는 변경하지 않았다. PyPI version metadata의 권고 없음은 조회 당시 사실이며 전체 취약점 부재 보증과 구분한다.
- `npm --prefix desktop run build`, lint, strict TS/Pyright agent, Ruff, 새 UI JS syntax 검사 통과.
- host 단위18개 통과. 기존 framing/SecretStore/계정 분리·공통 TS/Python JSON Schema fixture를 유지한다.
- workspace `test_ai_core`4개 통과: 실제 사용한 순수 core의 import 경계, PR/commit 입력 hash·토큰 추정·출력 validator 동등, 정책 양쪽 원문 검사, 명시 provider factory/환경 주입.
- 기존 `test_ai_output_validation.py`24개와 `test_ai_contracts.py`29개 통과. 실제 provider·GitHub·DB는 호출하지 않았다.

중간 strict 검사에서 새 내부 메서드 접근·외부 JSON의 unknown type을 발견해 명시 grant/transaction port와 입력 검증/cast로 수정했다. 호스트 locale의 기본 cp932 파일 읽기가 실패하여 UTF-8을 명시했다. 검증 실패를 통과로 집계하지 않는다.

## 최종 실행 결과

승인한 P04 범위의 구현·검증을 완료했다. 임시 fixture에서만 schema1/2→3 migration·backup·실패 복구를 실행했다. 실제 앱 userData·서버 DB·서비스·사용자 프로젝트는 변경하지 않았다.

- workspace 전체 43개 통과(23.135초): 기존 복구/격리 검사와 snapshot 6개·탐지 3개·core 4개 포함. 캡처 도중 HEAD/index/목록/선택 파일 변경, 비밀·생성물 제외, 고정 preview·재시작·암호화·원본/index 보존을 확인했다.
- 기존 provider 42개·multi-provider 17개·출력 제한 10개 통과. 앞서 통과한 validator 24개·DTO 29개와 함께 기존 AI 계약 회귀를 확인했다. 테스트 transport/fixture만 사용했다.
- 격리 agent freeze 성공. 선택적 `tzdata` hidden import 경고가 있었으며 이번 UTC/명시 offset 범위에는 IANA timezone 기능을 사용하지 않는다. 추가 의존성을 설치하지 않았고 frozen agent 시작과 실제 Electron 검사가 통과했다.
- 새 frozen agent로 실제 Electron changes·foundation·projects·auth·remote-compat 5개 시나리오 통과. 실제 IPC의 capture/preview/detect/plan 왕복, DPAPI·CSP·sender 검사, 기존 프로젝트와 P03 페이지 회귀를 포함한다. 계획을 생성했지만 프로젝트 명령은 실행하지 않았다.
- `GITVIZ_VERIFY_P04=1 npm run package` 성공. P03 검증 패키지는 보존했다. P04 패키지를 표준 사용자·PATH=System32에서 실행해 exit 0과 PASS marker, 포함 agent hash 일치를 확인했다. 이는 개발 호스트 검증이며 새 clean VM 인수로 집계하지 않는다. 설치된 Git fixture와 Node 경로 메타데이터를 사용했다.

패키지 증거는 `.validation/p04/package-3cfbe04868aa4cee94970705781d71ec/{acceptance.json,stdout.log,stderr.log}`에 보존했다. 독립 fixture 화면의 `desktop:auth-status` handler 미등록 메시지 1건은 stderr에 남아 있으며 P04 판정은 완료된 전체 시나리오의 PASS marker와 exit 0을 함께 요구한다.

**남은 별도 gate:** P03 실제 서버 OAuth·웹/앱 동시 사용 및 기존 권한/구·신 서버 호환 인수는 미실행이다. P04 완료가 이를 대체하지 않는다. Q06 최종 제품 지원표와 Q08 보존정책 결정도 후속 범위다. installer·서명·배포·외부 OAuth/AI 호출은 수행하지 않았다. P05는 착수하지 않았다.

계획 본문/scripts는 command_plan AEAD에 보관하고 local_operation에는 opaque planId만 남겨 멱등 재조회에서도 원문을 평문 저장하지 않는다. snapshot payload/줄 텍스트는 AEAD, metadata line_map은 줄 번호/종류만 저장한다. Q08 미정 때문에 자동 삭제 TTL을 만들지 않았으며 보존정책 미정을 표시한다. 실행 approve/run operation과 원문 외부 전송은 아직 capability에 없다.
