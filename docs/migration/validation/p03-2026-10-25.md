## 승인·상태

사용자는 P03 진행, Q05의 기존 웹 shared GET 권한 유지, Q10/A08의 flow5분·session8시간·refresh 없음, 기존 CDN과 동일 버전의 자산 번들링, 전용 PostgreSQL 검증, 독립 P03 검증 패키징·실행을 각각 승인했다. 실제 서버 배포·외부 OAuth 검증은 별도 승인 단계로 남기는 데 동의했다. 전역 공유 정책의 소급 변경이나 로컬 결과 공유 승인이 아니다.

현재는 **코드 구현과 로컬·격리 검증 완료, 실환경 인수 대기**다. 로컬 HTTP/실제 PostgreSQL/실제 Electron fixture·패키지 실행 결과와 실제 GitHub OAuth·배포 서버 결과를 구분한다. staging OAuth는 미실행이다. T11/T14/T15의 실제 서버 인수가 남아 P03 전체 또는 출시 완료로 선언하지 않는다.

시작 브랜치 `fix/search-score-caption`, HEAD `a8351f0bf24c78625990f8756e5a03fc42a002c6`. 기존 dirty 변경을 복원하지 않았다. `.validation/p03/baseline.json`에315개 기존 소스/설정 파일의 hash를 저장했다. `.env` 내용을 도구로 조회·출력하거나 수정하지 않았다. 기존 회귀의 자동 dotenv 설정 상속은 아래 실패 수정에 구분한다. 기존 DB·서비스·서버 venv·Git 이력은 변경하지 않았다.

## 보안·복구의 구체 동작

서버 인증은 기본 꺼짐이다. HTTPS public origin·secure browser cookie·독립32byte 발급 응답 key가 필요하다. 신규 transaction/session 표만 추가하고 기존 user/분석/AI 표를 바꾸지 않는다. 새 head는 `b7e1d9c3a502`, 직전은 `a9d2f4c6e8b0`다. migration은 정적 DDL이고 운영 startup에서 DDL을 실행하지 않는다. downgrade는 데이터 삭제 없이 명시 거부한다.

flow 발급은 직접 연결 IP hash별5분10회, PostgreSQL advisory lock으로 worker 간 제한한다. proxy의 forwarding header를 인증 없이 신뢰하지 않는다. 각 flow5분·poll2초·session8시간이며 refresh는 없다. row lock·challenge/pollSecret hash 비교·browser session binding·CSRF·displayCode·사용자 승인으로1회 발급한다. 같은 exchange key는 AES-GCM으로 보관한 동일 응답을60초 재조회한다. 다른 key는409, 만료/거절/폐기는 거부한다. 만료 flow는 replay 유예 뒤 다음 발급 시 인증 표에서만 청소한다. proxy 공유 IP 및 향후 운영 cleanup 주기는 배포 시 조정·검증 대상이다.

토큰은 main 메모리와 OS 보호 파일에만 두고 renderer/agent/URL에는 주지 않는다. 서버는 token hash만 저장하고 짧은 발급 응답만 별도 key로 암호화한다. bearer+web session cookie 혼합은401이다. 웹 Origin/CSRF는 그대로 검사하며 `DesktopPrincipal`이 middleware에서 검증된 요청만 AI CSRF 예외다. desktop validation 오류는 secret 입력값을 복사하지 않는다.

main remote는 HTTPS origin 고정·redirect 금지·cookie jar 없음·renderer 인증 헤더 거부·응답 header subset·요청256000bytes/동시8개·timeout15초·응답8MiB 상한을 둔다. mutation을 timeout/5xx 때문에 자동 재전송하지 않는다. 로그인 exchange만 동일 key를 유지하며 Retry-After를 따른다. 401/계정 generation 변경이면 예전 응답을 적용하지 않는다. 이미 인증해 사용 중인 화면에서는 renderer가 private 화면·snapshot 메모리 cache·gitviz storage를 지우고 로컬 홈으로 이동한다. 초기 미로그인 화면은 로그인 UI를 유지한다. 원격 본문은 디스크 cache하지 않는다. logout은 화면·gitviz storage를 정리하고 네트워크 실패 시 OS 보호된 폐기 대기 토큰만 남겨 다음 실행에서 인증 복원 대신 폐기를 재시도한다. 저장장치 실패·동일 OS 사용자 침해까지 완전 방어한다고 주장하지 않는다.

번들 UI만 native bridge를 갖는다. 고정된 HTML 목록·app host·main frame을 검증하며 script/eval/remote frame/webview를 열지 않는다. 기존 inline style 때문에 web 문서에 style-src unsafe-inline을 사용하되 script-src는 self이고 inline handler/eval은 허용하지 않는다. 기존 GitHub 링크는 HTTPS repository 경로 allowlist와 native 취소 기본 확인 뒤 시스템 browser로 연다. remote avatar는 CSP에서 허용하지 않아 외부 이미지를 자동 요청하지 않는다. 기업 proxy/CA·전체 실제 데이터 조합·실제 제공자 품질은 미검증이다.

## 실패와 수정

초기 sandbox의 TestClient가 응답하지 않아 중단했고 OS 보호 hard-link 검사2개도 실패했다. 표준 사용자 외부 실행에서는 통과했으며 보안 동작을 약화하지 않았다. HTTP fixture가 기본 `session` cookie를 써 혼합 인증 테스트가 실패했고 실제 앱과 같은 `gitviz_session`으로 수정했다. inline handler 변환기는 지원되지 않는 다중 문장 표현에서 파일 쓰기 전 멈췄고 명명형 동작으로 변환한 뒤39개 순수 UI 회귀와 실제 탭 클릭을 확인했다. Electron45 console-message event 타입을 실제 선언에 맞춰 수정했다.

최초 PostgreSQL 제어는 Windows 자식 프로세스 대기로 지연되어 중단했다. `Start-Process -WindowStyle Hidden`과 pg_ctl 자신의 종료만 기다리는 방식으로 바꿨고 새 클러스터에서 검사·종료를 확인했다. 기존 backend test2개가 과거 head `f6b8d0a2c4e1`을 기대해 실패했다. 새 additive head로 기대값만 갱신하고 기존 데이터·열·작업 복구 검사는 유지했다. 이 수정 중 한 줄 들여쓰기 오류로 실행이 중단되어 문법을 고친 뒤 재검증했다.

## 실행·남은 gate·rollback

서버는 새 migration·검증된 DB TLS/CA를 먼저 준비한 후 `DESKTOP_AUTH_ENABLED=1`, HTTPS `DESKTOP_PUBLIC_ORIGIN`, 별도 `DESKTOP_AUTH_RESPONSE_KEY`, secure session cookie를 설정한다. 이 기록은 실제 운영 설정 변경이나 배포 승인이 아니다. 앱 main은 승인한 HTTPS `GITVIZ_SERVER_ORIGIN`이 없으면 원격 미설정으로 표시하고 로컬 기능을 유지한다. 서버 OAuth client secret는 앱에 포함하지 않는다.

남은 gate는 실제 승인 서버의 시스템 browser OAuth·현재 계정 권한·구/신 서버·웹/앱 동시 사용 인수다. HTTPS staging origin과 additive API/DB 배포 준비, 실제 배포·외부 호출 별도 승인이 필요하다. fixture 성공을 실제 OAuth/AI 품질 또는 전체 E 동작 matrix로 승격하지 않는다. rollback은 desktop 발급 off·세션 폐기·기존 web 유지이며 인증 표와 기존 사용자 데이터는 보존한다. P04 이후는 별도 승인이다.
