# P01 기반 구현과 검증 기록

기록일: 2026-10-24 (Asia/Seoul). [단계 계획](../13-implementation-plan.md) · [테스트 전략](../12-testing-strategy.md) · [P00 기준](implementation-baseline.md).

## 승인과 상태

사용자는 P01 착수, 격리 설치·테스트·빌드, workspace cryptography48.0.0→50.0.2 교체를 각각 승인했다. 초기에는 부분 구현으로 기록했으며, 현재는 [후속 검증](p01-remaining-2026-10-24.md)의 clean VM·22개 중단 경계·실제 NTFS 용량 고갈 인수까지 통과해 **승인된 P01 기반 범위 구현·검증 완료**다. 출시 가능 판정은 별도다. P02 이후는 진행하지 않았다.

## 구현과 책임 경계

격리 상태 UI·health 전용 preload·sender/main-frame/app-origin 검사·CSP·원격 navigation 제한을 구현했다. main은 고정 bundled agent만 최소 환경으로 실행한다. stdout은 공통 schema로 검증하는 엄격 JSONL이다. stderr는 원문을 버리고64KiB 초과 시 종료한다. requestId 위조·중복 완료·잘린 EOF·추가 필드·JSON 중복key·크기/깊이 상한을 거부한다. renderer에는 파일·shell·DB·key·generic invoke를 노출하지 않는다.

agent는 서버 import 없이 handshake→내부 key bootstrap→ACL/Job Object/부모 감시→SQLite 검사로 ready를 구성한다. 실제 OS 수명은 기동 직후 연결하며 DB는 협상·bootstrap 후 연다. 지원 schema 불일치는 data 생성 전에 차단한다. SQLite는 schema_meta만 만들고 단일 writer·FK·WAL·migration 전 backup·rollback을 사용한다. 업무 표는 없다. main의 OS 보호 key와 agent의AES-256-GCM을 사용해 system 시험 자료를 재시작 후 확인한다. key 부재·변조·다른 AAD에서 실패하고 기존 암호문을 덮어쓰지 않는다.

서버·기존 frontend·DB·Redis/Celery는 수정/실행하지 않았다. 별도 환경은 이미 Git 제외된 `.validation/venv-workspace`에 생성했고 Pyright도 일치시켰다. 보조 파일 `desktop/.gitignore`는 node_modules/dist/out 제외에 한정한다. source/프로젝트·AI·Git·에디터·runner API는 구현하지 않았다.

## 의존성

직접 버전은 desktop/package.json, 전이 버전/integrity는 desktop/package-lock.json에 고정한다. TypeScript7과 typescript-eslint 지원 범위가 달라6.0.3을 사용했다. Node 타입은24.19.2다. Forge umbrella type은 무관한 macOS/새Node 선언 문제가 있어 config를 자체 TypeScript 검사 후 Forge 실제 package 검증으로 확인한다. skipLibCheck는 사용하지 않는다.

Python17개 배포물의 Windows x64/CPython3.12 호환 wheel SHA-256을 requirements-workspace.lock에 고정했다. 최초 설치 후 public PyPI metadata로 hash를 생성하고 실제 wheel download의 --require-hashes로 검증한다. 다른 OS/ABI 지원 증거는 아니다.

npm audit:216 dependency entries에 알려진 권고0개. Python 버전별 PyPI vulnerabilities 조회에서 cryptography48.0.0에7개 식별자(중복 가능)가 발견됐다. 승인 후50.0.2로 변경했고 현재17개 배포물의 해당 metadata 권고는0개다. 권고0이 취약점 부재 보증은 아니다.

npm lock 라이선스 집계: MIT165, BSD-2-Clause9, Apache-2.0 16, ISC14, BlueOak-1.0.0 9, BSD-3-Clause2, MIT OR CC0-1.0 1. Python은 MIT/MIT-0/BSD/Apache/PSF 계열과 PyInstaller의 GPL+배포 예외, hooks-contrib 별도 조건이 포함된다. 최종 배포 notice/SBOM·서명·installer 검토는 P10에 남는다. 의존성 목록을 법률 적합성 전체 보증으로 취급하지 않는다.

## 실패와 수정

- 기본 sandbox TEMP의 권한 때문에 ensurepip와 파일/SQLite fixture가 실패했다. venv 재생성과 실제 GUI는 승인 범위에서 sandbox 밖 실행, 시험 TEMP는 workspace 전용 경로로 조정했다. OS 보안 설정은 끄지 않았다.
- SQLite context manager가 connection을 닫지 않아 Windows backup 파일 잠금이 남았다. production backup과 시험 연결에 contextlib.closing을 적용했다.
- 초기 Forge 모듈 해석·Node 타입·ESLint·Pyright 오류를 수정했다. 실패 build 뒤 남은 과거 compiled test 실행은 최종 증거로 세지 않고 성공 build 후 재실행했다.
- venv python.exe redirector의 중간PID 때문에 부모 종료 fixture가 실패했다. 실제 OS interpreter로 부모 handle을 정확히 검사했고16개 시험을 다시 통과했다. 제품 agent는 frozen exe다.
- Forge agent 경로 오류 및 production node_modules 제외를 수정하고 package와 실제 ASAR Ajv 로드를 확인했다.

## 변경 보호

착수 당시390개 비무시 파일의 메모리 SHA-256/부재 기준과 비교했다. 기존 파일 변경은 migration의12/13/14 문서3개뿐이며 나머지387개의 바이트/부재 상태는 동일하다. 신규51개(제품·schema·검사/설정·lock·보조 ignore·실행 기록)를 추가했다. 기존 소스·설정·패키지·사용자 dirty 변경은 보존했다. ignored 환경/빌드/시험 산출물은 별도다. 실제 .env는 읽거나 기록하지 않았다.

## 산출물과 복구

앱: `desktop/out/GitVizWorkspace-win32-x64`, agent: `dist/workspace-agent/agent`, 패키지 agent: `resources/agent`. 앱 직접 실행은 current-user app data에 key/시험 암호문/SQLite를 만들며 사용자 프로젝트는 열지 않는다. 개발 start는 resource 경로에 bundled agent가 없으면 unavailable로 표시된다.

실패 시 앱/agent 종료·진단/정합 backup 보존. 기존 서버·사용자 프로젝트·기존 dirty 변경은 복원 대상이 아니다. 새 환경/산출물 삭제는 경로 확인과 사용자 선택 후 별도 처리한다. commit/push/reset/clean·서버 서비스·외부AI·installer·배포는 수행하지 않았다.

## 후속 잔여 검증

[2026-10-24 잔여 검증](p01-remaining-2026-10-24.md)에서22개 중단 지점과 실제 SQLite FULL·암호문/key 손상 복구를 추가 검증했다. 위16/10개는 이전 실행이며 최신 결과19/13개와 구분한다. 이후 같은 기록의 최종 절에서 clean VM·물리 NTFS 용량 고갈까지 통과했다. P01 기반 범위는 검증 완료이며 후속 단계·출시 검증과 구분한다.
