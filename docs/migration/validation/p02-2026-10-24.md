# P02 프로젝트·읽기 전용 Git 구현 기록

기록일: 2026-10-24 Asia/Seoul. [단계 계획](../13-implementation-plan.md), [F01](../05-functional-specification.md), [RPC](../07-api-design.md), [보안](../10-edge-cases-and-security.md).

## 승인과 현재 상태

사용자는 P01 완료 후 P02 착수와 계속 진행, 이어서 “P02 재빌드·Electron 검증·검증용 패키징”을 승인했다. agent 재freeze·실제 Electron 인수·검증용 Forge package와 번들 실행까지 통과했다. 승인된 P02 구현·인수 범위는 완료다. 실제 앱 userData와 서버 DB를 migration하지 않았다. installer·서명·배포 및 P03 이후는 포함하지 않는다.

현재 브랜치 `fix/search-score-caption`, HEAD `a8351f0bf24c78625990f8756e5a03fc42a002c6`. 기존 dirty 파일은 복원/정리하지 않았다. 기존 서버·API·collectors/clone_manager·원래 frontend 파일은 수정하지 않았다. 새 frontend workspace 경로만 추가했다. Git commit/push나 사용자 원본 프로젝트 Git 쓰기 작업은 없다. Git fixture 변경 명령은 생성한 임시 저장소에 한정했다.

## 파일과 연결 경로

신규 `app/workspace/{projects,scoped_files,git_service}.py`, `desktop/src/projects.ts`, `frontend/pages/workspace.html`, `frontend/js/workspace/{projects,status}.js`, `tests/workspace/{test_projects,test_scoped_files,test_git_status}.py`, `desktop/tests/projects.e2e.ts` 및 이 기록.

기존 P01 `migrations/store/dispatcher/contracts`, 공통 request/response/fixtures JSON, desktop DTO·agent/main/preload/asset protocol/build script, package/lock의 앱 자체 version만0.2.0으로 갱신했다. 새 의존성·전이 dependency 변경은 없다. 기존 회귀 테스트는 schema2·추가 named bridge 기대값을 반영했다. P01 physical fixture는 타입 주석 및 SCHEMA_VERSION 기반 backup 파일명만 보강했다. 이전 물리 검증 artifact를 재실행한 것으로 보고하지 않는다.

호출 경로: bundled workspace UI → 명명형 preload → sender 검증 main → native 선택/확인 → 엄격한 RPC → Projects → LocalGit/LocalStore. renderer는 root/metadata scope/선택 ticket을 보내거나 받지 않는다. path 정보는 native 확인과 agent 내부 저장에 한정한다. raw invoke·임의 executable·URL·shell command API는 노출하지 않는다.

## schema와 구체 계약

local schema2는 local_project·project_setting(recentLimit)·local_operation을 추가한다. v1→v2 전 `pre-v2-UUID.sqlite3` backup API와 integrity check·flush·publish를 수행하고 transaction migration한다. handshake의 schema 범위는2..2, RPC protocolVersion은1을 유지한다. 기존 schema1 binary와 schema2의 교차 쓰기는 허용하지 않는다. 기존 OS 보호 key와 system probe envelope/AAD 형식은 유지한다.

- `workspace.projects.selectAndRegister`는 main 전용 phase=inspect/register다. inspect에 selectedRoot·metadataScopes·expandedRoot·reconnectApproved, register에 TTL60초 selectionId를 사용한다. renderer의 selectAndRegister는 인자를 받지 않으며 native dialog의 실제 선택만 사용한다.
- root 확대·외부 gitDir·commonDir·이동한 root 재연결을 각각 native 취소 기본값으로 확인한다. 외부 gitDir 승인 전 commondir 파일을 읽지 않는다. 같은 canonical root는 기존 ID, 이동한 동일 identity는 명시 재연결 후 ID 유지/version 증가다. 자동 탐색·clone은 없다.
- list는 cursor UUID·limit1..50, get/status/settings/unregister는 명시 projectId다. status recentLimit1..100, settings는 expectedVersion·recentLimit, unregister는 expectedVersion이다.
- mutation은 공통 idempotencyKey UUID와 canonical body hash를 transaction에 기록한다. 동일 key/body 재전송은 기존 결과, 다른 body는 CONFLICT다. unregister 후에도 replay tombstone은 보존한다. Q08 보존 정책 미정이므로 임의 TTL 삭제를 추가하지 않았다.

## Git 실행과 한계

고정 설치 위치의 Git을 argv 배열/shell=false로 실행한다. status porcelain-v2 -z·제한된 log·object-format만 조회한다. 각 command4초, stdout256KiB·stderr64KiB, response200KiB, pin 대상2만 항목 상한이다. root/metadata와 조상·하위 항목을 Windows 삭제 공유 없이 pin하며 reparse point가 있으면 조회 전에 거부한다. 동일 OS 사용자의 완전 격리는 보장하지 않는다.

선택 root 밖 본문을 읽지 않도록 worktree metadata만 별도 grant한다. 외부 config include·object alternates·partial clone/promisor는 차단한다. system/global config·fsmonitor·untracked cache·clean/process filter·lazy fetch·transport 허용을 제한한다. ownership 실패에서 safe.directory 우회를 하지 않는다. submodule은 ignore-submodules=all로 내부를 펼치지 않으며 sparse metadata·필터 비실행에 따른 상태 차이·reparse/config 제한을 UI에 명시한다. 비UTF8/상한 초과는 typed 오류다.

staged와 unstaged는 같은 path라도 별도 배열, rename oldPath·untracked·conflict·unborn/detached·40/64자리 OID를 구분한다. commit subject·author·경로는 textContent로 렌더링한다. UI는 프로젝트와 목록 요청 세대를 관리한다. 실제 DOM 인수에서 이전 프로젝트의 지연 응답 차단과 HTML 문자열의 텍스트 표시를 확인했다.

## 실제 Electron·패키지 인수와 복구

승인 후 위 명령을 순서대로 실행했다. main/native dialog 테스트 adapter는 독립 E2E entry에서만 주입하고 실제 production IPC에 테스트 우회 스위치를 추가하지 않았다. 폴더 선택·확인 UI 응답은 adapter로 제공하고 실제 renderer/IPC/frozen agent/Git을 사용했다. 사람이 native dialog를 클릭하는 수동 인수와 구분한다.

E2E에서 native 선택 취소·root 확대 취소/승인·worktree metadata 승인, 실제 Git·stdio·renderer, 강제로 늦춘 A 응답 후 B 유지, XSS 문자열 text 렌더링, CAS/replay/unregister 및 원본/index hash 불변을 확인했다. INVALID_REQUEST와 RESOURCE_NOT_FOUND console 출력은 의도적으로 잘못된 요청을 보낸 거부 검사이며 전체 프로세스 exit0을 확인했다.

검증 package는 `desktop/out/GitVizWorkspaceVerify-win32-x64`다. 개발 호스트의 표준 사용자로 실행했고 설치된 Node/Python은 검출되었으므로 clean VM 결과로 표시하지 않았다. acceptance/foundation/diagnostic-summary JSON은 `.validation/p02/evidence`에 보존했다. acceptance의 SHA256은 다음과 같다.

- EXE: `AC767486513B635450182A8569A6451D79535F55E6824EC5217EBC1D66A1CC9B`
- app.asar: `CEFCEE02F93557CA2852A6CBE93B0E5E18709376F82E53589F7D405C04ED9B16`
- agent: `BA6A047AC4DC56BE351615969615CAB08D33BE118E55525165111B69BF23D8C4`

실패한 검사의 신규 artifact와 증거는 보존하며 사용자 DB를 건드리지 않는다. 기존 P01 실행 package는 별도이며 schema2 DB를 구 binary로 강제 열거나 downgrade하지 않는다. v1 backup 복원은 별도 디렉터리에서 명시 전환해야 한다. P02 범위 C01 인수는 완료했으며 제품 전체 출시 가능 판정은 P09/P10과 분리한다.
