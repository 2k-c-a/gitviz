# 공동 편집 파일 묶음·미리보기 설계 (AD-34)

작성일: 2026-11-04 · 코드 기준: `dc68209` · 상태: **1단계 구현(2026-11-04, `feat/collab-file-set`)**, 2·3단계 미구현 · 결정 기록: [AD-34](ARCHITECTURE_DECISIONS.md) · 현재 공동 편집: AD-29 · [문서 안내](../index.md)

이 문서는 확정된 설계와 1단계 구현을 정리한 것이다. 구현에서 설계와 달라진 점과 남은 한계는 §10에 있다.

소유자 결정(2026-11-04):
- "폴더 대신 파일을 고르면 그 파일과 import 관계인 파일만 공동 편집", "HTML은 분리된 CSS·JS도 작동".
- 공유 범위를 시작 파일의 **상위 폴더까지 넓히는 것을 허용**한다.
- 미리보기에서 **외부 CDN을 허용**한다.
- **이미지·폰트를 지원**한다.
- 세션 루트 기준 **상대 경로를 화면에 보여 주는 것을** "렌더러는 파일 경로를 받지 않는다" 규칙의 **예외로 인정**한다(절대 경로·루트 밖 경로는 계속 화면에 주지 않는다).
- §9의 권장안 6개를 그대로 채택한다("위 권장안대로 정한다"). 본문의 한도·범위는 이 결정으로 확정된 값이다.

## 1. 목표와 범위

| 단계 | 내용 | 이 문서의 범위 |
|---|---|---|
| 1단계 | 시작 파일 + 참조 추적으로 파일 묶음을 공동 편집하고, HTML·CSS·JS·이미지·폰트를 앱 안에서 미리보기 | **상세 설계** |
| 2단계 | Python 실행(앱 안 WASM, Pyodide) | 방향만 (§8) |
| 3단계 | C/C++·Java 실행(누른 사람 PC의 설치된 컴파일러) | 방향만 (§8) |

바뀌지 않는 원칙(AD-29 유지):
- 파일은 호스트 PC에만 있고, 디스크를 읽고 쓰는 것은 호스트 앱의 main 프로세스뿐이다. 저장은 호스트가 누를 때만 한다.
- 서버는 자리 관리와 메시지 전달만 하고 파일 내용을 저장하지 않는다. 최대 3명.
- 렌더러에는 절대 경로를 주지 않는다. 세션 루트 기준 상대 경로만 준다(위 예외).

## 2. 현재 구조 (확인)

- 세션당 파일 하나: [collab-files.ts](../../desktop/src/collab-files.ts)가 native 대화상자로 파일 하나를 열고 핸들·이름·본문·언어를 화면에 준다. 100KB 이하 UTF-8 텍스트, 심볼릭 링크 거부.
- 서버: [community_collab.py](../../app/services/community_collab.py)는 3자리, 30초 만료, 사용자당 분당 relay 1200회. relay 본문 `data`는 base64 최대 200,000자(약 150KB, [community 스키마](../../app/schemas/community.py)의 `CollabRelayRequest`), `kind`는 `update|sync-request|sync|awareness`. 세션 생성 본문은 `file_name` 하나와 `language`.
- 편집기 번들: `desktop/scripts/collab-editor.entry.mjs` → `dist/ui/web/js/collab-editor.bundle.js`(CodeMirror 6 + Yjs). 공유 문서에는 `Y.Text` 하나가 있다.

## 3. 파일 묶음 만들기

### 3.1 흐름

1. 호스트가 **시작 파일** 하나를 고른다(native 대화상자, 지금과 같다).
2. 호스트 앱 main이 시작 파일에서 참조를 따라가며 파일을 모은다(너비 우선, 방문한 경로는 다시 읽지 않음).
3. 호스트에게 **묶음 확인 화면**을 보여 준다: 루트 폴더, 포함할 파일(텍스트·바이너리 구분, 크기), 제외된 참조와 이유, 찾지 못한 참조(§3.4). 루트 밖 참조 때문에 제외된 것이 있으면 "루트를 넓히기"(§3.2)를 제안한다. 호스트가 확인해야 세션을 만든다.
4. 확인된 파일마다 핸들을 만들고, 화면에는 `{handle, 상대 경로, 종류, 본문 또는 바이트, 언어}` 목록만 준다.

### 3.2 루트와 경계

- **기본 루트:** 시작 파일이 있는 폴더.
- **루트 넓히기(결정: 허용):** 호스트가 묶음 확인 화면에서 상위 폴더로 넓힐 수 있다. 넓히면 다시 분석해 목록을 갱신한다. 한도(결정 §9-3):
  - 시작 파일이 Git 저장소 안이면 **저장소 루트(`.git`이 있는 폴더)까지**.
  - 저장소 밖이면 **세 단계 위까지**.
  - 어느 경우에도 드라이브 루트(`C:\`), 사용자 프로필 폴더 자체(`C:\Users\<이름>`)와 그 바로 아래 알려진 폴더(바탕 화면·문서·다운로드 자체)는 루트가 될 수 없다. 넓은 범위에서 의도치 않은 파일이 섞이는 것을 막는다.
  - 확인 화면에 현재 루트를 짧은 표기(예: `…\my-site`)로 보여 준다. 이 표기는 호스트 화면에만 쓰고 참여자에게는 보내지 않는다.
- 다음은 따라가지 않고 "제외"로 표시한다:
  - 루트 밖으로 나가는 경로(정규화 후 `..`로 시작), 절대 경로, 드라이브 문자, UNC
  - 심볼릭 링크·정션(경로의 어느 단계든), 장치 이름(`CON`, `NUL` 등)
  - 이름이 `.`로 시작하는 파일·폴더(`.git`, `.env` 등), `node_modules`
  - 허용 목록 밖의 확장자
- 외부 주소(`https://…` CDN 등)는 묶음에 넣지 않는다. 미리보기가 직접 불러온다(§6.3).
- 대소문자: Windows 경로는 대소문자를 무시해 같은 파일을 두 번 넣지 않는다. 상대 경로는 실제 디스크 표기와 `/` 구분자로 쓴다.

### 3.3 허용 파일과 크기

| 종류 | 확장자 | 공동 편집 | 한도(결정 §9-5) |
|---|---|---|---|
| 텍스트 | `.html` `.htm` `.css` `.js` `.mjs` `.cjs` `.json` `.svg` `.txt` `.md` (2·3단계: `.py` `.c` `.h` `.cpp` `.hpp` `.java`) | 가능 | 파일당 100KB, 최대 20개, 합계 1MB |
| 이미지(결정: 지원) | `.png` `.jpg` `.jpeg` `.gif` `.webp` `.avif` `.ico` `.bmp` | 읽기 전용 | 파일당 2MB |
| 폰트(결정: 지원) | `.woff2` `.woff` `.ttf` `.otf` | 읽기 전용 | 파일당 2MB |
| 바이너리 합계 | — | — | 최대 30개, 합계 10MB |

- SVG는 텍스트로 다룬다(편집 가능).
- 바이너리는 내용이 아니라 **실제 파일 형식(앞부분 시그니처)**도 확장자와 맞는지 확인한다. 맞지 않으면 제외.
- 오디오·비디오·실행 파일·압축 파일은 넣지 않는다.

### 3.4 참조 분석 규칙

| 파일 | 따라가는 참조 | 분석 방법 |
|---|---|---|
| HTML | `<link rel~=stylesheet\|icon\|preload\|modulepreload href>`, `<script src>`, 인라인 `<script type=module>`의 import, `<img src>`·`srcset`, `<picture><source srcset>`, `<iframe src>`(HTML이면 재귀), 인라인 `style=""`·`<style>` 안의 `url()`·`@import` | `parse5`(HTML 표준 파서) |
| CSS | `@import`, `url(...)`(이미지·폰트 포함, `@font-face src`) | 주석·문자열을 고려한 작은 토크나이저 |
| JS | 정적 `import`/`export ... from`, 문자열 리터럴 `import('./x.js')`, `new Worker('./w.js')`, `new URL('./x', import.meta.url)` | `es-module-lexer`(WASM, 주석·문자열 구분) |
| SVG | `<use href>`·`<image href>` 중 상대 경로 | `parse5`의 XML 모드 또는 단순 속성 추출 |
| JSON·TXT·MD | 따라가지 않음 | — |

- 쿼리·해시(`style.css?v=2`, `#id`)는 떼고 경로만 본다.
- `/`로 시작하는 경로: **세션 루트 기준으로 해석한다**(결정 §9-1).
- `<a href="about.html">` 같은 페이지 링크는 자동으로 따라가지 않고 "추가 후보"로 보여 준다. 다중 페이지 사이트에서 묶음이 불필요하게 커지는 것을 막는다.
- 패키지 이름(`import 'lodash'`)은 "찾지 못함"으로 표시한다. CDN 주소(`https://…`)는 외부 참조로 따로 보여 준다.

### 3.5 찾지 못한 참조와 수동 추가

정적 분석으로 찾을 수 없는 것: `fetch('data.json')`, 변수로 만든 경로, 실행 중 만드는 태그, 패키지 이름. 이를 위해:
- 묶음 확인 화면과 편집 화면에 "찾지 못한 참조" 목록을 보여 준다(파일·줄과 문자열). 판단할 수 있는 문자열 리터럴(`fetch('data.json')`)과 `<a href>`는 "추가 후보"로 보인다.
- 호스트만 "파일 추가"를 쓸 수 있다. 후보를 누르거나 native 대화상자로 고르며 §3.2·§3.3 규칙을 똑같이 적용한다(루트 밖이면 "루트를 넓힐까요?"를 묻는다).

### 3.6 편집 중 새로 생긴 참조 — 호스트 승인 필수

참여자가 `<img src="../private/photo.jpg">`를 적어 넣으면 호스트 앱이 그 파일을 읽어 모두에게 보내게 될 수 있다. **호스트 PC 파일을 빼내는 통로**가 되지 않도록:
- 호스트 앱은 공유 문서가 바뀌면(디바운스 1초) 묶음 안 파일을 다시 분석해 새 참조를 찾는다. 디스크에서 새 파일을 **자동으로 읽어 공유하지 않는다.**
- 새 참조가 §3.2·§3.3 규칙을 통과하면 호스트 화면에 "`img/photo.jpg`를 공동 편집에 추가할까요? (추가한 사람: ○○)" 확인을 띄운다. 호스트가 승인해야 main이 읽어 공유한다. 거절·무시하면 그 경로는 세션 동안 다시 묻지 않는다.
- 새 참조가 루트 밖이면 묻지 않고 거부한다. 루트 넓히기는 호스트가 직접 할 때만 한다(참여자 편집이 루트 확장을 유도하지 못하게).
- 참여자에게는 "호스트 승인 대기" 표시만 보인다.
- 아직 디스크에 없는 새 파일은 1단계에서 만들지 않는다(미리보기에서 404). 새 파일 만들기는 후속 과제로 둔다.

## 4. 공유 문서·편집 화면

- Yjs 문서 하나에:
  - `Y.Map('files')`: 키 = 상대 경로, 값 = `Y.Text`(텍스트 파일).
  - `Y.Map('assets')`: 키 = 상대 경로, 값 = `{sha256, size, mime}`(바이너리 목록만. 바이트는 Yjs 밖으로 따로 보낸다, §5).
  - 경로는 호스트만 넣는다. 참여자가 맵에 넣은 항목은 호스트 앱이 무시하고 저장·미리보기 대상에서 뺀다.
- 화면: 파일 트리(또는 탭) + 편집기 + 미리보기 버튼. 이미지·폰트는 트리에서 미리보기만 된다. 커서(awareness)에 현재 파일 경로를 함께 싣는다.
- 저장: 호스트의 "저장"은 변경된 텍스트 파일만 파일별로 지금과 같은 방식(해시 확인 → 임시 파일 → rename)으로 쓴다. 묶음 전체의 원자성은 보장하지 않으며 결과를 파일별로 보여 준다. 바이너리는 저장하지 않는다(읽기 전용).
- 언어 표시: 기존 `LANGUAGES` 표를 따르고 2·3단계에서 C/C++·Java CodeMirror 언어를 더한다.

## 5. 동기화

텍스트와 바이너리를 다른 경로로 보낸다(결정 §9-2).

- **텍스트 — 파일별 동기화:** `sync-request`·`sync`에 파일 경로(선택 필드 `path`)를 붙여 파일마다 따로 주고받는다. 파일당 100KB라 relay 한 번(약 150KB)에 들어간다. 이후 편집은 지금처럼 `update`로 보낸다. 큰 메시지를 쪼개는 장치가 필요 없고, 한 파일 동기화가 실패해도 다른 파일에 영향이 없다.
- **바이너리 — 조각 전송:** 새 `kind` `asset`으로 호스트가 파일을 128KB 조각(base64 약 171K자)으로 나눠 보내고, 받는 쪽이 `Y.Map('assets')`의 `sha256`과 맞는지 확인한 뒤 메모리에 둔다. 늦게 들어온 참여자는 필요한 자산만 호스트에게 요청(`asset-request`)한다. 10MB 상한이면 사람당 약 80조각으로 분당 1200회 한도 안에 든다.
- **서버 변경:** `CollabRelayRequest.kind`에 `asset`·`asset-request`를 더하고 선택 필드 `path`(상대 경로 형식 검사, 최대 400자)를 둔다. 서버는 여전히 저장하지 않는다. 바이너리 조각이 Redis pub/sub·SSE를 지나므로 사용자당 분당 바이트 상한(예: 20MB)을 relay 횟수 한도와 함께 둔다.
- 세션 생성 본문의 `file_name`은 시작 파일 이름으로 쓰고, 선택 필드 `file_count`를 더한다(목록 화면 표시용).

## 6. HTML·CSS·JS 미리보기

### 6.1 방식

- 각자 자기 앱에서 **자기 공유 문서 상태**로 그린다. 저장하지 않은 수정도 보이고, 디스크를 읽지 않는다(참여자 PC에는 파일이 없다).
- 앱 전용 프로토콜 `gitviz-preview://<미리보기ID>/<상대 경로>`: main이 요청 경로를 묶음의 상대 경로로 바꿔 렌더러에서 받아 둔 메모리 내용(텍스트 스냅숏, 바이너리 바이트)을 돌려준다. 묶음에 없으면 404.
  - 브라우저가 상대 경로를 푸므로 `<link>`, `<script src>`, ES 모듈 import, CSS `url()`·`@import`·`@font-face`, `fetch('data.json')`(묶음에 있으면)가 그대로 동작한다. `/`로 시작하는 경로는 자연히 세션 루트로 풀린다.
  - `Content-Type`은 확장자로 정하고 `X-Content-Type-Options: nosniff`를 붙인다. 미리보기ID는 미리보기 창마다 새로 만든 무작위 값이라 다른 세션 내용을 부를 수 없다.
  - 프로토콜은 `standard`·`secure`로 등록해 ES 모듈·`fetch`가 동작하게 한다.
- 렌더러 → main으로 넘기는 것은 `{상대 경로: 내용}` 묶음뿐이고, 편집 후 500ms 디바운스로 갱신·새로고침한다.
- 묶음 안의 다른 HTML로 가는 링크(`<a href="about.html">`)는 미리보기 안에서 이동할 수 있다.

### 6.2 격리 (남이 쓴 JS가 내 앱에서 실행된다)

- 별도 `WebContentsView`(또는 창). `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`, **preload 없음**, 전용 session partition(`preview:<ID>`, 메모리 전용 — 쿠키·저장소가 디스크에 남지 않음).
- `will-navigate`·`will-redirect`로 미리보기 출처 밖으로의 최상위 이동 차단(외부 링크는 차단하고 "브라우저로 열기"를 묻지 않는다), `setWindowOpenHandler`로 새 창 거부, 다운로드 거부, 권한 요청(카메라·마이크·위치·알림·클립보드 읽기 등) 모두 거부, devtools는 개발 빌드만.
- 미리보기를 닫거나 세션이 끝나면 partition을 지우고 프로토콜 핸들러에서 그 ID를 뺀다.

### 6.3 외부 CDN (결정: 허용)

범위(결정 §9-4):
- **허용:** `https:`로 불러오는 스크립트·스타일·이미지·폰트·미디어(`script-src`·`style-src`·`img-src`·`font-src`·`media-src`에 `https:`), 그리고 `fetch`·`XMLHttpRequest`·WebSocket의 `https:`·`wss:`(`connect-src`) — 예제 코드가 외부 API를 부르는 경우가 흔하다.
- **차단:** `http:`(암호화 없음), `file:`, 다른 앱 프로토콜, 사설·루프백 주소(`localhost`, `127.0.0.1`, `10.*`, `192.168.*` 등, `session.webRequest`에서 막는다 — 남이 쓴 JS가 내 PC나 내부망의 서비스를 두드리지 못하게).
- **표시:** 미리보기 상단에 "외부 사이트에 연결함: cdn.jsdelivr.net 외 2곳"처럼 실제 접속한 호스트를 보여 준다. 보는 사람이 **"외부 연결 끄기"**를 누르면 그 미리보기에서만 묶음 안 파일로 제한한다.
- CSP 예: `default-src gitviz-preview: https: data: blob: 'unsafe-inline' 'unsafe-eval'; connect-src gitviz-preview: https: wss:; frame-ancestors 'none'; form-action gitviz-preview:`.
- 위험 수준: 보는 사람이 외부 웹 페이지 하나를 여는 것과 비슷하다. 외부 사이트는 보는 사람의 IP와 공유된 코드가 보내는 내용을 볼 수 있다. preload·Node가 없어 앱 기능·PC 파일에는 닿지 않는다.

## 8. 2·3단계 방향 (요약)

- **Python:** 앱 안 Pyodide를 Web Worker에서 실행. 파일 묶음을 가상 파일 시스템에 올려 `import`가 동작한다. 패키지 설치(micropip)·네트워크는 처음에 끈다. 시간 제한은 Worker 종료로. 참조 추적은 `import x`·`from .a import b`를 루트 아래 `.py`로 해석.
- **C/C++·Java:** 실행 버튼을 누른 사람 PC에 설치된 컴파일러(gcc·clang·MSVC, JDK)로 실행. 공유 문서를 임시 폴더에 복사해 컴파일·실행하고, Windows Job Object로 시간·메모리·프로세스 수를 제한한다(AppContainer로 네트워크·사용자 파일 차단 검토). 남이 바꾼 줄을 보여 주는 실행 전 확인을 둔다. 참조 추적: C/C++는 `#include "x.h"`와 같은 이름의 `.c`/`.cpp`, Java는 import와 같은 패키지를 폴더 구조로 해석.
- 실행 결과 공유는 기본 본인만, 공유하면 출력 텍스트만 relay로 보낸다(서버 저장 없음).

설계와 달라진 점·남은 한계:
- 루트 금지 폴더(드라이브·사용자 폴더·바탕 화면 등)는 **넓힐 때만** 적용한다. 시작 파일이 바탕 화면에 바로 있으면 그 폴더는 기본 루트로 쓸 수 있다(호스트가 그 파일을 직접 골랐고, 참조된 파일만 들어간다).
- 새 참조 승인 화면에 "추가한 사람"은 표시하지 않는다(Yjs 변경에서 작성자를 확정할 수 없다). 경로만 보여 준다.
- 미리보기의 사설 주소 차단은 URL의 호스트 이름·IP 표기 기준이다. 공개 이름이 사설 IP로 풀리는 DNS 재바인딩은 막지 못한다.
- 미리보기 상단 표시 대신 미리보기 창 제목과 공동 편집 화면에 외부 연결 호스트를 보여 준다. "외부 연결 끄기"는 공동 편집 화면의 버튼이다.
- 문서 구조가 바뀌어 AD-29(파일 하나) 방식의 이전 앱과는 함께 편집할 수 없다. `file_count`가 없는 세션에 참여하면 안내만 하고 나온다.
- 시험: 앱 단위 테스트 `desktop/tests/collab-bundle.test.ts`(참조·경계·승인·넓히기·한도·차단 규칙), e2e `phase3-flows`(실제 두 번째 Yjs 편집기와 묶음 확인·후보 추가·파일별 동기화·이미지 조각 전송·새 참조 승인·미리보기 CSS·이미지·차단·저장·손님 동기화), 서버 `test_community`(path 형식·자산 전달·바이트 상한). 실제 두 PC·실제 서버에서의 사용은 시험하지 않았다.
