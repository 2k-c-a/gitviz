# AI 팀 권한·공유·보고서 계약 (S13)

개인 자료를 팀에 보여 주는 단계라 **권한 계약을 먼저 정하고** 구현한다. 이 문서가 기준이며, 구현이 달라지면 이 문서와 [AI_INTERFACE_CONTRACT.md](AI_INTERFACE_CONTRACT.md) 18절을 함께 고친다.

## 1. 원칙

1. **개인 자료는 자동으로 공유되지 않는다.** 팀을 만들거나 가입해도, 저장소를 팀에 연결해도 어떤 개인 결과·문서도 팀에 보이지 않는다. 자료의 작성자가 팀을 지정해 명시적으로 공유할 때만 보인다.
2. **보이는 범위 = 팀 역할 ∩ 현재 저장소 접근 ∩ 현재 유효한 공유.** 세 가지를 요청마다 다시 확인한다(저장된 허가를 믿지 않는다). 하나라도 빠지면 존재를 숨기거나 차단한다.
3. **개인 결과 캐시는 팀과 섞이지 않는다.** 개인 결과·재사용(작업 지문)·멱등 키·예산은 그대로 개인 owner 기준이다. 팀 자료는 별도 테이블(공유 기록·보고서)에만 있고 개인 작업을 팀 작업으로 바꾸지 않는다.
4. **외부 확인 뒤에 다시 판단한다.** 저장소 접근 확인(GitHub)은 잠금 밖에서 하므로, 확인이 끝난 뒤 팀 행을 잡은 채 구성원·공유 존재·유효성·공개 범위 세대를 다시 확인하고 같은 잠금 안에서 내용을 읽는다. 구성원·공유·세대를 바꾸는 쪽은 같은 팀 행을 FOR UPDATE로 잡아 읽는 쪽(FOR SHARE)과 서로 기다린다. 인계 대상 공유의 내용은 고정한 버전을 그대로 읽는다(최신 값을 읽지 않는다).
5. **실패는 닫는다.** 판단할 수 없으면(권한 확인 장애, 공유 이후 원본 수정, 범위 변경) 내용을 보여 주지 않고 이유를 알린다.

## 2. 역할과 권한

| 동작 | 관리자(admin) | 멤버(member) | 조회자(viewer) |
|---|---|---|---|
| 팀 이름 변경·삭제 | ✓ | | |
| 구성원 초대·역할 변경·제거 | ✓ | | |
| 팀 저장소 연결·해제 | ✓ (본인이 그 저장소에 접근 가능해야 함) | | |
| 내 자료를 팀에 공유 / 내가 한 공유 해제 | ✓ | ✓ | |
| 남이 한 공유 해제 | ✓ | | |
| 공유된 자료 보기 | ✓ | ✓ | ✓ |
| 보고서 생성 | ✓ | ✓ | |
| 보고서 보기 | ✓ | ✓ | ✓ |
| 보고서 삭제 | ✓ | 내가 만든 것 | |
| 탈퇴 | ✓ | ✓ | ✓ |

- 팀에는 **관리자가 항상 1명 이상**이다. 마지막 관리자의 탈퇴·강등·제거는 거절한다(409).
- 초대는 **수락해야 구성원이 된다**(초대받은 사람이 거절·무시하면 아무것도 보이지 않는다). 초대 대상은 GitViz에 로그인한 적 있는 GitHub 사용자만 지정할 수 있으며, 찾을 수 없거나 모호하면 같은 응답(404)이다.
- 팀·구성원 정보는 구성원에게만 보인다. 구성원이 아니면 팀의 존재도 알 수 없다(404).

## 3. 공유

- 공유할 수 있는 자료: **코드 리뷰 결과**(지적의 제목·분류·위치·내용과 작성자의 검증 판정. 코드 원문·인용은 제외, 결과에 붙은 이력 근거의 수치 포함)와 **인계 대상의 준비 상태**(항목별 상태만. 메모·링크·문서 본문은 제외).
- 공유하려면 ① 내 자료이고 ② 그 저장소가 팀에 연결돼 있고 ③ 내가 지금 그 저장소에 접근할 수 있고 ④ 내 역할이 관리자/멤버여야 한다.
- 공유 기록은 원본이 삭제되면(결과 보관 기간 만료 포함) 함께 사라진다. 저장소 연결을 해제하면 그 저장소의 공유도 사라진다.
- 인계 대상 공유는 **공유한 시점의 대상·준비 정보 버전에 고정**된다. 작성자가 이후에 바꾸면 공유는 `outdated`가 되어 내용이 숨겨지고, 다시 공유해야 한다(수정한 내용이 모르는 사이에 팀에 퍼지지 않는다).
- 구성원이 팀을 떠나거나 제거되거나 조회자로 낮아지면 **그 사람이 한 공유는 모두 삭제**된다.
- 팀에는 **공개 범위 세대(visibility_epoch)**가 있다. 구성원 제거·역할 변경·저장소 연결 해제·공유 해제가 일어나면 올라간다.

## 4. 보고서

- 결정적으로 정리한다. **모델을 호출하지 않는다**: 코드 전송·팀 BYOK·팀 예산이 필요 없고, 미검증 지적이 문장 생성 중에 사실로 바뀔 수 없다. (모델 서술을 넣으려면 아래 6절의 합의가 먼저 필요하다.)
- 생성 요청은 팀에 연결된 저장소 중 **보고 대상 저장소**를 고른다. 생성자는 그 저장소 모두에 접근할 수 있어야 하고, 현재 유효한 공유만 쓴다. 결과에는 **원본 목록(source_manifest)**(공유 id·원본 id·작성자·저장소·해시·피드백 기준·고정 버전)과 생성 시점의 `visibility_epoch`를 보관한다. 보고서는 수정할 수 없다.
- **보고서를 보려면** 팀 구성원이면서(역할 무관) ① 보고서의 세대가 팀의 현재 세대와 같고 ② 원본 공유가 모두 아직 유효하며 ③ 조회자가 **원본의 모든 저장소에 현재 접근할 수 있어야** 한다. 하나라도 어긋나면 차단하고(`REPORT_BLOCKED`, 이유 목록) 내용을 주지 않는다. 일부 저장소만 볼 수 있는 사람에게 같은 전문을 보여 주지 않는다 — 그 사람의 범위에 맞춰 **새로 생성**한다.
- 권한이 줄어든 뒤의 기존 보고서는 **차단된다**(자유 문장에서 민감한 부분만 지울 수 있다고 가정하지 않는다). 새 범위로 다시 생성해야 한다.
- 생성은 팀 행을 잠그고 한 트랜잭션으로 끝낸다. 생성 중 구성원·공유 변경은 그 뒤에 처리되고, 변경이 일어난 뒤에는 이미 만든 보고서가 차단된다. 생성이 끝나기 전에 세대가 바뀌었음을 발견하면 저장하지 않고 409로 끝낸다.
- 내용: 저장소별 공유된 리뷰 결과 목록, **문제 집계**, 준비 상태 개요.
  - **문제 집계는 사람이 `valid`로 검증한 지적만** 센다. 검증하지 않은 지적은 "검토 대기"로, `uncertain`은 "불확실"로 따로 세고, **`false_positive`는 문제 집계에서 제외**한다(참고 건수만).
  - 같은 지적 후보(지문 일치)는 **후보로만** 묶고 문제 수에 합치지 않는다. 사람이 각 결과에서 판정한 것만 문제로 센다.
  - 판정은 "작성자의 판단"이며 GitViz가 확인한 것이 아니다. 선택하지 않은·공유되지 않은 자료는 "확인되지 않음"이다.
  - 준비 상태: 공유된 인계 대상의 항목별 상태("준비 완료"는 작성자 기록). 메모·링크는 싣지 않는다.
- 피드백이 바뀌면 보고서는 차단되지 않고 `stale`(기준 변경)로 표시한다.

## 5. 비용·키·실행 주체

- **팀 키·팀 예산을 만들지 않는다.** 개인 BYOK 키는 개인 소유로 남고 팀에 공유되거나 팀 작업에 쓰이지 않는다. 개인 작업·결과·재사용 지문·멱등 키·사용량 예산은 지금까지와 같이 개인 owner 기준이다.
- 보고서 생성은 비용이 없다(모델 호출 없음). `ai_jobs`에 팀 작업을 만들지 않으므로 실행 주체 스키마도 바꾸지 않는다.

## 6. 합의가 필요한 것 (구현하지 않음)

모델이 쓴 팀 보고서를 도입하려면 먼저 정해야 한다.
1. 누구의 키로 호출하는가: 생성자의 개인 키(비용·전송 동의가 그 사람에게만 있음) vs 팀 키(관리자만 등록, 팀 예산).
2. 개인 키를 쓸 때, **다른 사람의 공유 자료**를 그 사람의 키로 외부 제공자에게 보내는 것에 대한 공유자 동의(공유 시점 동의 vs 생성 시점 확인).
3. 팀 예산 한도·소진 시 동작, 생성자가 떠난 뒤의 키 처리.

## 7. 출시 전 확인

실제 인증 경로(인증된 GitHub 사용자로 팀·초대·저장소 접근 확인)와 운영 스냅샷 검증은 이 단계에서도 **출시 전 확인 항목**이다. 저장소 접근은 GitHub 기준이라 테스트에서는 접근 확인 함수를 대체해 시험했다.
