# 실제 웹 통합 테스트 — 2026-10-03

사용자가 GitHub OAuth 로그인/콜백을 실제 수행한 뒤 웹페이지에서 분석을 요청했다. FastAPI 서버, 별도 Celery solo 워커, Redis 논리 DB 14, 전용 PostgreSQL 18 DB `gitviz_test_web_20261003`를 사용했다. 공유 원격 DB는 변경하지 않았으며 수집 함수나 큐를 mock/eager로 대체하지 않았다.

| 대상 | 결과 | 기록 |
|---|---|---|
| octocat/Hello-World 신규 분석 | 성공 | 워커 약 11.4초, 스냅샷 #1, 병합 PR 파일 상세 1/1 |
| 2k-c-a/gitviz 신규 분석 | 성공 | 워커 약 37.0초, 스냅샷 #2, PR 파일 상세 23/23 |
| GitViz 재분석 | 성공 | 워커 약 7.6초, 스냅샷 #3 생성, 결과 보기에서 최신 #3 조회 |

시간은 Celery 로그의 처리 시간이며 대규모 성능 평가가 아니다.

GitViz 관측 구간 커밋 86개, 현재 파일 129개, 실제 기여자 3명이다. 새 계산 버전 `gitviz-2026.10-priority-v3`로 파일 129개의 우선순위가 저장됐다. 수집 기본 브랜치 커밋 91개와 원시 전체 커밋 97개는 관측 구간 건수와 다르다. 재분석 전후 원시 커밋 97개와 파일 변경 행 22,352개는 유지됐다.

PR 파일 상세 3,304행이 저장됐다. 공동 변경은 PR 단위, 사용 단위 14개, 대규모 변경 제외 9개, 결과 쌍 13개였다. 23/23은 파일 상세가 최소 한 행 있는 비율로 모든 페이지의 완전성을 독립 확인한 값은 아니다.

## 웹에서 확인한 흐름

- 로그인 → URL 입력 → 분석 요청 HTTP 200 → Redis 전달 → 별도 Celery task 수신/성공 → job done·스냅샷 저장.
- 결과 보기 → 타임라인 활동/기여자/커밋 유형 표시.
- 타임라인→협업 네트워크→코드분석에서 repo=2/snapshot=2 유지.
- 파일 목록·트리·BF·점수·결합도 표시. 파일 상세에서 기여 지분과 양방향 공동 변경 비율 조회.
- 재분석 후 결과 보기는 최신 snapshot=3으로 이동.
- Hello-World 기본 180일 관측 커밋 0개는 과거 원시 수집 실패가 아니라 구간 밖의 변경이다.

협업 네트워크는 노드 3개, 엣지 0개였다. 양의 협업 엣지나 리뷰 방향 표시를 검증한 것은 아니다.

## 발견 사항

시각화 상세 설명에 마지막 refactor 이후 기간, IDF 기본 정렬이라는 이전 문구가 남았다. `VISUALIZATION_HANDOFF.md`에 재현과 수정 지시를 추가했다.

재분석 시 원시 Contributor 수는 3→4, 미해결 수는 0→1로 증가했다. 신규 미해결 Contributor의 연결 커밋은 0개이고 분석 구간 실제 기여자는 3명이다. 수집 담당에게 기여자 재생성/별칭 매핑의 반복 실행 안정성 점검을 전달했다. 수집·시각화 코드는 변경하지 않았다.

화면 증거는 `.validation/web-evidence/`에 저장했다. 서버와 워커는 계속 실행 중이며 localhost:8000에서 최신 결과를 확인할 수 있다. `.env` 변경 없이 프로세스 환경변수로 전용 DB를 연결했다.

위험 순위 정확도, 대규모 성능, 모든 저장소의 수집 완전성을 입증한 결과는 아니다.
