# 지표 정의와 해석

검토일: 2026-10-23 · 코드 기준: `a8351f0` · [분석 계약](analytics.md) · [보존 원문](../archive/originals/METRICS.md)

확인: 현재 코드의 산식·분모·해석 제한을 정리한다. 미확정: 경험적 타당성·실제 수집 완전성은 별도 검증이다.

## 지표의 의미

- **유지보수 점검 우선순위**: `maintenance_priority = (P(change_freq)+P(churn)+P(bugfix_count))/3`. P는 관측 변경이 있는 현재 파일 집합 안의 백분위 순위다. 동률은 중간 순위, 모든 값이 같거나 파일이 하나이면 0이다. 관측이 없는 파일은 null이다. 0은 안전을 뜻하지 않는다. `risk_score`는 호환 별칭이고 0.7은 표시 정책일 뿐 상위 30%가 아니다.
- **관측 기간**: 기본 `[T-180일,T)`, 명시한 시작/종료 구간은 그대로 적용. refactor 메시지로 초기화하지 않는다. 기본 구간은 타임라인·협업·요약을 포함한 새 스냅샷 전체 입력에 적용된다. `current_risk`, `structural_risk`는 새 결과에서 null이며 새 점수에 포함하지 않는다.
- **BF 추정치**: 관측 구간의 파일 변경 커밋 수에서 누적 기여 80% 이상을 차지하는 최소 인원. BF=1은 한 명에게 변경 기여가 집중됐다는 뜻이다. 실제 지식 보유 인원이 한 명이라는 뜻이 아니다. `project_bus_factor`는 기존 API 호환용 이름으로, 실제 값은 파일별 BF 추정치의 중앙값이다.
- **Ownership Entropy**: 변경 기여 비중의 Shannon Entropy. `entropy_normalized = H/log2(n)`(n>1), 기여자 1명은 0, 식별된 기여가 없으면 null. 높은 값은 위험으로 가산하지 않는다. 기여자 수·표본 수·주 기여자 비율·미식별 비율을 함께 확인한다.
- **결합도**: 공동 변경 횟수 / 두 파일 변경 횟수 중 작은 값. 대칭 비율이며 방향별 영향 확률이 아니다. 최소 공동 변경 2건인 쌍을 반환한다. 기본 정렬은 원 결합도·표본 수, `sort_by=idf`는 IDF 보정 정렬이다. 파일 상세는 기본적으로 선택 파일→상대 파일의 과거 동반 변경 비율 순이고, `sort_by`를 주면 전체 후보를 그 기준(coupling|idf)으로 정렬한 뒤 자른다. IDF 점수는 1을 넘을 수 있고 검증된 개선을 뜻하지 않는다.
- **커밋 유형 confidence**: 분류 규칙에 부여한 값. 검증된 정확도나 결함 확률이 아니다.
- **검색 예비 점수**: 활동성 55 + 이슈 관리 45(총 100). 활동성은 마지막 push가 최근일수록 높고 365일 이상이면 0점이다. 이슈 관리는 `open_issues / (stars + 50)`이 낮을수록 높으며(스타가 적은 저장소의 과도한 감점을 막는 완충), 활동성이 낮으면 상한이 걸려 활동성 0점일 때 최대 18점이다. 인기도(stars)와 언어는 건강도 지표가 아니라 점수에서 제외하고 카드에 따로 표시한다. open_issues에는 PR이 섞여 있다. 코드 품질을 보장하지 않으며 상세 분석 점수와는 다른 척도다.

## 계산 수정

- 계산 버전은 `gitviz-2026.10-priority-v3`. 기존 스냅샷은 수정하지 않고 새 분석으로 생성한다. 서로 다른 버전의 직접 비교는 기존대로 거부한다.
- 우선순위의 비교 집합은 현재 살아 있고 구간 내 변경이 있는 파일이다. 버그 수정 횟수는 메시지 규칙에 따른 약한 정답이며, Entropy·BF·Co-change·refactor 횟수는 점수에 포함하지 않는다.
- 대규모 변경은 스냅샷 계산 시 `changed_file_count >= max(15,ceil(0.1*N))`로 판정한다. N은 현재 목표 SHA의 파일 수를 대용으로 사용한다. 과거 파일 수가 아니며 parameters의 `large_change_size_basis=target_tree_proxy`로 공개한다. 수집된 플래그와 원본 행은 수정하지 않는다. 변경 수가 없으면 수집된 파일 연결 수를 쓰므로 부분 수집은 과소 추정될 수 있다.
- PR 상세가 있는 비율(`pr_file_coverage`)은 파일 상세가 한 행 이상 있는 PR 비율이다. PR 내부 모든 파일·전체 GitHub PR 수의 완전성을 보장하지 않는다. 커밋 fallback은 PR 없음 / PR 상세 없음 / 수집된 PR 전부 필터됨을 구분한다.
- BF80의 `observation_count`는 식별된 기여의 변경 횟수다. 미식별 변경은 분포에서 빠지며 `unidentified_share`로 따로 표시한다. 표본 5건 미만의 low_support는 표시 정책이다.

- 스쿼시·리베이스 병합 저장소는 PR의 원본 커밋이 기본 브랜치에 들어오지 않는다. 수집기는 최근 PR(기본 1000개, `PR_HEAD_FETCH_LIMIT`, 0이면 끔)의 head를 `refs/gitviz/pr/<번호>`로 받아 `git log --all` 수집에 포함하고, 함께 수정(co-edit) 계산만 스냅샷 범위 밖의 PR 소속 커밋(`raw_table_prefix`)을 읽는다. 다른 지표의 범위는 바꾸지 않아 같은 변경이 두 번 집계되지 않는다. 기존 저장소는 `FORCE_FULL_RECOLLECT=1`로 전체 재수집해야 PR 원본 커밋이 채워진다(증분 수집은 `since` 이후 커밋만 읽는다). 관측 구간에 PR이 제한 수보다 많으면 오래된 PR의 원본 커밋은 연결되지 않는다.
- 공동 수정은 같은 PR의 커밋 중 실제로 같은 파일을 수정한 기여자끼리 집계한다. 같은 PR 참여만으로 모든 파일을 수정한 것으로 간주하지 않는다. 중복 커밋은 PR·파일·기여자 단위에서 제거한다. 연결된 PR 커밋/파일 기록이 부족하면 관계가 누락될 수 있다.
- 중심성 계산은 양의 협업 강도의 역수를 거리로 사용한다. Louvain 군집 계산은 원래 협업 강도를 사용한다. 작은 양의 강도를 0으로 반올림하지 않는다.
- BF의 누적 80% 판정은 정수 변경 횟수를 비교해 부동소수점 오차를 피한다.
- 폴더의 지표 평균은 지표별로 값이 있는 하위 파일을 같은 가중치로 집계한다. 폴더별 평균을 단순 평균하지 않는다.

## 검증

```text
python tests/server/test_analytics_calculations.py
python tests/server/test_metric_policy.py
node tests/frontend/test_metric_display.cjs
```

`test_analytics_calculations.py`는 운영 DB 연결 없이 실제 분석 함수와 공동 수정 SQL을 실행한다. SQLite 표본 데이터로 집계 의미를 확인하며, PostgreSQL 운영 DB 통합 검증을 대체하지 않는다. `test_metric_display.cjs`는 DOM 없이 프론트 집계와 지표 설명을 검증한다.

`test_metric_policy.py`는 동률·결측·고정 구간·refactor 초기화 제거·미식별 기여·PR fallback·방향별 결합도·스냅샷 정렬을 검사한다. 정확도 실험은 별개이며 변경 빈도 단독, churn 단독, 두 지표 평균, 세 지표 평균과 이전 모델을 같은 미래 구간에서 비교해야 한다. 새 스냅샷만으로 이전 모델을 재계산할 수 없으므로 변경 전 스냅샷과 고정 입력을 보존한다.

추가/삭제 줄 수가 null인 변경이 있으면 해당 파일의 churn과 종합 점수는 null, `evidence_status=metrics_missing`으로 반환한다. 누락 값을 0으로 치환하거나 가중치를 재분배하지 않는다. 수집기가 이미 누락을 0으로 저장했다면 백엔드는 진짜 0과 구분할 수 없다.
