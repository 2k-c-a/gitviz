## 승인 범위와 처리

확인: 처음에는 1~4단계 추가 작성만 승인받았고, 이후 사용자가 기존 파일의 이동·수정·삭제를 모두 허용하며 정리를 요청했다. 이 후속 승인을 반영해 문서 재배치·현재 안내 수정·참조 갱신을 수행했다. 정책 결정·배포·DB 변경·유료 모델 호출은 포함하지 않는다. 기존 `.gitignore` 로컬 변경은 그대로 보존한다.

|---|---|---|
| 0 감사 | 원본 31개·소스·설정·Git·선택 검사를 대조 | [인벤토리](inventory.md)의 범위·한계 |

## 정리한 구조

```text
docs/
  index.md
  audit/          # 인벤토리·실행 기록·원본 해시·경로표·검사
  product/        # 현재 범위·후속 계획·분석 실험 계획
  architecture/   # 실행 구조·접근·snapshot·backfill
  contracts/      # 지표·AI·수집·프론트 계약
  operations/     # 설치·복구·provider
  decisions/      # 확인한 결정·상충·미확정
  validation/     # 현재 상태·과거 증거 목록
    protocols/    # 문서·회귀·AI 평가 절차
  archive/
    index.md
    originals/    # 이전 경로 구조 그대로의 31개 원문
```

확인: 루트는 README를 진입점으로 유지한다. 예전 HANDOFF·METRICS·SNAPSHOT·검증 기록은 원본 보관소로 이동했고 현재 역할별 안내로 대체했다. `migrations/README`는 설치·검증 문서의 위치를 안내한다. 과거 문서의 상단 경고를 고치기 위해 원문을 변경하지 않고 보관소 index에서 Historical 의미를 분명히 했다.

## 경로·보존·복원

[기존 해시 baseline](preservation-baseline.json)은 재생성하지 않았다. [이동 경로표](relocation-map.json)가 각 이전 경로의 원문 위치와 현재 대응 문서를 기록한다. 보관소는 이전 디렉터리 구조를 유지하므로 과거 문서 간 상대 링크도 성립한다. `.gitattributes`는 보관 원문의 줄바꿈을 포함한 바이트를 그대로 저장한다.

현재 README·지표 정의·평가 절차는 유지 문서이고 보관 원문과 역할이 다르다. 기준값이 바뀌면 현재 문서·코드·검증을 갱신하고 과거 증거는 바꾸지 않는다. 복원이 필요하면 경로표에서 원문을 확인해 별도 작업 경로로 복사하고 현재 안내를 자동 덮어쓰지 않는다.

## 검증 결과 파일

새 검증 결과는 `reports/validation/<종류>-<UTC시각>-<고유값>.json`에 기록한다. [출력 도구](../../tests/server/validation_reports.py)와 검증 스크립트 기본 출력 경로를 갱신해 예전 루트·docs JSON을 다시 만들거나 Historical 결과를 덮어쓰지 않게 했다. live 수집 스크립트의 명시적 `--output`은 유지한다. 이번 정리에서 실제 수집·운영 DB 검증을 수행하지 않았다.

## 완료 조건

- 원본 31개의 SHA-256이 보존 위치에서 baseline과 일치한다.
- 경로표는 baseline 전체를 빠짐없이 대응하고 존재하는 현재 문서를 가리킨다.
- 현재 README·현재 문서·보관소의 로컬 링크와 명시/heading anchor가 유효하고 docs/index에서 도달 가능하다.
- 원본 inventory가 모든 보관 경로를 포함하고 이전 파일 경로가 불필요하게 남지 않는다.
- 현재 운영 안내는 폐기 기능·과거 profile 한도·과거 기본 기간을 그대로 적용하지 않는다.
- 정책 충돌은 근거·추정·미확정으로 구분한다. 과거 통과·실패·중단·대역 한계를 유지한다.
- 문서·출력 도구의 실패 감지 회귀가 통과한다.

실행은 [검사 절차](../validation/protocols/document-consistency.md), 결과·미실행 범위는 [현재 상태](../validation/current-status.md)에서 확인한다. 추가 문서 정리 권한을 재요청하지 않는다. 실제 제품 정책·출시 판단은 각각의 근거로 결정한다.
