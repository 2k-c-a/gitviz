# 정보 구조·사용자 흐름·디자인 방향

기준: `c459f29` · 2026-10-29 · **이 문서 전체는 미래 설계 제안이다.** [구현 사실](project-audit.md) · [문제 근거](ux-problems.md) · [와이어프레임](wireframes.md) · [구현 계획](implementation-plan.md)

## 1. 제품 원칙과 범위

1. 사용자의 첫 질문인 '어느 저장소의 어떤 시점인가'를 항상 보여준다.
2. 전체 현황 → 사람/관계/파일 → 근거 순으로 정보 깊이를 늘린다. 독립 작업인 코드 전송·명령 실행·파일 적용은 각 단계의 확인을 보존한다.
3. 실제 관측, 상대 점수, AI 추론, 검증 명령 결과를 다른 의미로 표시한다.
4. 앱의 디자인은 이어지게 만들되 로컬 privileged renderer와 원격 renderer의 보안 경계는 유지한다.
5. 웹·데스크톱 기술을 유지한다. React 도입·프레임워크 교체·새 차트 라이브러리 설치를 선행 조건으로 삼지 않는다.

## 2. 전체 내비게이션

```text
GitViz
├─ 저장소 탐색                     전역 시작점: 검색 / 최근·내 분석 탭
├─ [현재 원격 저장소 owner/repo]    선택기 + 결과 시점
│   ├─ 개요                       분석 대시보드
│   ├─ 개발 활동                  활동 / 기여자 탭
│   ├─ 협업                       그래프 + 상위 쌍
│   ├─ 파일                       파일 목록·계층 / 공동 변경 탭
│   ├─ AI 리뷰                    대상 선택 / 실행·결과 / 이력
│   └─ 분석 이력                  스냅샷 목록 / 두 결과 비교
├─ 로컬 작업                      기존 기능 보존, 원격 분석과 모드 구분
│   ├─ 프로젝트·변경              폴더 등록, Git 상태, 고정 입력·diff
│   ├─ 리뷰·제안                  로컬/허용 cloud 리뷰, 제안·승인·복구
│   ├─ 영향·검증                  정적 영향, 명령 계획·실행, 전후 비교
│   └─ 알림                       기존 통합 알림 목록/대상 복귀
├─ 작업함                         현재 원격 분석/리뷰 조회 진입
└─ 설정                           계정 / 모델·API 키 / 로컬 환경 / 앱·진단

공통 상세 패널: 기여자 / 파일 / 선택 협업 쌍 / 진행 상세
```

작업함은 UI의 조회 진입 통합이다. 현재 remote 분석 폴링, AI 작업 목록, local inbox의 수명주기를 하나의 서버 job 모델로 통합한다는 제안이 아니다. 현재 창의 최대16개 원격 추적 제한과 앱에서 관찰한 상태 전환만 알린다는 경계를 유지한다. 모든 저장소를 상시 백그라운드 감시하는 기능은 범위 밖이다.

| 기능 | 형태와 이유 | 기존 기능 대응 |
|---|---|---|
| 저장소 탐색 | 독립 전역 화면. 검색과 최근/내 분석은 같은 선택 작업의 탭 | index/search/myprojects를 목적 중심으로 재구성 |
| 분석 대시보드 | 저장소 안 '개요' 독립 화면. 전체 요약과 다음 행동만 | summary/timeline/top-files/top-pairs 일부 재사용 |
| 개발 활동 | 독립 화면 안 활동/기여자 탭. 일시적 사람 선택은 상세 패널 | timeline/heatmap/top-contributors |
| 기여자 상세 | 공통 우측 패널, 작은 창은 콘텐츠 전체 상세. 독립 최상위 메뉴로 늘리지 않음 | contributor drilldown |
| 협업 | 독립 화면. 그래프와 쌍 목록을 나란히 탐색 | network/top-pairs |
| 파일 분석 | 독립 화면 안 목록·계층/공동 변경 탭. tree는 보조 뷰 | code-analysis/tree/bus-factor/coupling |
| 파일 상세 | 공통 패널. 점수 근거·수정자·공동 변경 탭 | file drilldown |
| AI 리뷰 | 독립 작업 화면. 대상→파일→미리보기→결과는 단계 상태, 이력은 탭 | ai-review/ai-state |
| 분석 이력 | 독립 화면. 개요·활동·파일 헤더의 같은 결과 선택기에서 연결 | history/snapshot compare |
| 설정 | 전역 화면 안 탭. key는 원격/일회용 보관 범위 표시 | 기존 renderKeys + local 환경 제어 |
| 로컬 도구 | 별도 모드의 목적별 하위 뷰. 기존 기능을 숨겨 폐기하지 않음 | workspace 각 섹션 재배치 |

```text
├ 앱 헤더: 뒤로·앞으로 | owner/repo [원격] | 계정·작업함 ───┤

│ 메뉴       ├──────────────────────┬─────────────────────┤
│            │ 주요 콘텐츠          │ 상세 패널(선택 시)   │
```

제목 표시줄을 커스텀으로 교체하지 않는다. 메뉴는 표준 Windows 역할을 유지하되 실제 history/zoom 등 동작을 다음 단계에 점검한다. 전역 탐색은 현재 메뉴와 저장소 하위 메뉴를 시각적으로 구분한다. 키 입력 포커스가 editor/input에 있을 때 앱 단축키가 가로채지 않도록 한다.

| 가용 콘텐츠 폭(CSS px) | 내비게이션·콘텐츠·상세 정책 |
|---|---|
| 1280 이상 | nav 208~224px, 나머지 유동 main. 상세는 기본 360px(320~480 가변). 표에 약640px 확보 안 되면 상세를 전체 뷰로 전환 |
| 960~1279 | nav 56px rail, tooltip+접근성 이름, 펼침 가능. 상세 기본320px. main 가용640px 미만이면 상세 전체 뷰 |
| 600~959 | nav 접기 버튼/overlay, 콘텐츠 한 열. 상세는 콘텐츠 영역을 대체하고 뒤로 복귀. toolbar 2줄, 표 내부만 가로 스크롤 |
| 높이400 부근 | 보조 상태 설명 접기, 헤더 합계 약120px 이내 목표. 행동 footer 고정 시 본문 padding으로 가림 방지, 경고는 펼쳐 읽을 수 있게 함 |

전체 body의 이중 스크롤을 피하고 main/panel 각각 scroll container를 정의한다. 상세 패널 열린 상태에서 창이 좁아져도 선택·뒤로 stack은 유지한다. 600×400, 900×640(현 기본), 1280×800, 1920×1080과 Windows 100/125/150/200% scaling을 검사한다. min window 상향으로 문제를 숨기지 않는다.

## 4. 맥락·뒤로 가기·필터 규칙

- 원격 분석 canonical context는 `repositoryId + snapshotId + formulaVersion`. 현재 `repo/snapshot/sort_by` URL 규칙을 유지한다. 새 패널 주소 매개변수는 구현 시 검증·허용목록을 정의한다.
- 같은 저장소 분석 탭 사이에는 snapshot과 sort 정책을 보존한다. 파일 경로 검색/기여자 선택/스크롤·graph camera는 view state로 저장하고 결과 ID별로 격리한다. API payload에 없는 검색 결과를 만들어내지 않는다.
- 다른 저장소로 전환하면 상세·filter·AI input/job·이전 snapshot을 해제한다. 원격 접근 확인 전 자동 local project 매핑 금지. 계정 변경은 관련 cache와 key UI 상태를 폐기한다.
- 상세 내부 back은 기여자→파일→다른 파일 stack을 한 단계 복귀한다. 앱 back은 화면 방문 이력이다. Escape는 가장 위 overlay/패널만 닫고 포커스를 원래 행으로 돌린다. 닫기와 작업 취소를 연결하지 않는다.
- URL의 snapshot이 없으면 서버가 돌려준 최신 ID로 확정한다. 사라진/권한 없는 snapshot은 명시 오류와 '최신 결과 열기'를 제공하며 조용히 다른 결과로 바꾸지 않는다.
- AI 결과는 분석 snapshot보다 `input/baseSHA/headSHA/profile/credentialVersion`이 기준이다. 분석 화면에서 진입해도 관측 snapshot과 현재 PR/commit의 고정 코드는 같다고 가정하지 않는다.
- 기간 선택: 기존 snapshot은 고정 기간 표시만. 활동 차트의 '최근3/6개월'은 저장 결과 내부 표시 범위임을 표시한다. 새 분석 기간 지정은 desktop 계약 의존 기능으로 보류한다.
- 키/동의 상태는 URL/localStorage에 넣지 않는다. 일회용 key를 세션 복구 기능으로 영속화하지 않는다.

## 5. 핵심 사용자 여정 A~H

### A. GitHub 저장소 검색 및 선택

진입: 저장소 탐색 → 검색 탭(한 곳에서 키워드 또는 GitHub URL) → 결과 목록 → 결과 열기/분석 시작.

사용자는 owner/repo·설명·언어·최근 갱신·기존 결과 여부를 확인한다. 예비 점수는 보조 열과 '메타데이터 기준' 설명으로 낮춘다. 이미 성공한 결과는 개요로, 진행 중이면 진행 패널로, 결과 없으면 분석 시작 버튼으로 연결한다. 검색0건은 다른 검색어/URL 입력, 429는 대기 후 재조회, 인증 필요는 현재 query를 보존하고 로그인 진입한다. 등록 여부와 ID를 확정하지 못하면 '결과 확인 재시도'이며 자동 새 분석을 하지 않는다.

최단 경로 목표: 검색 제출 → 결과 열기. 확인 가능한 기존 결과 열기에는 분석 시작 확인을 끼우지 않는다. 검색 API가 상위20건만 제공하는 현 UI를 기준으로 수신/표시 범위를 적는다.

### B. 분석 시작 및 진행 확인

진입: 탐색 결과의 분석 시작 → 저장소/계정 확인 → 요청 접수 → 진행 패널 → 완료 결과 개요.

패널에는 대기/수집/신원 정리/지표 계산/결과 저장, 실제 수집 건수, 마지막 갱신, GitHub 한도 재개 시각을 보인다. 총량 불명이면 임의 완료%나 남은시간을 만들지 않는다. 닫으면 작업은 지속한다는 문구와 헤더 작업 표시를 남긴다. 재진입은 기존 status GET이다. failed/stale/교체됨은 구분하고 마지막 성공 결과 열기를 제공한다. 완료는 서버 done+결과 ID 확인 후 이동한다. 재분석은 기존 결과를 읽는 동안 별도 새 결과를 만들며 기존 결과를 덮지 않는다.

### C. 전체 개발 활동과 주요 지표

진입: 개요 → 결과 기간/수집 상태 확인 → KPI 및 활동 bar → 개발 활동 또는 파일·협업으로 이동.

KPI는 구간 커밋·활성 기여자90일·릴리즈·버그 수정 **분류** 비율. 숫자 옆에 기준 기간/분모를 제공한다. 다음 행동은 점검할 파일, 주요 기여자, 상위 협업 쌍이다. 사용자가 더 보고 싶을 때만 상세 화면으로 이동한다. 비교는 분석 이력에서 이전/이후 결과를 명시 선택한다. 서로 다른 계산 버전은 같은 변화 지표로 비교하지 않는다.

### D. 기여자 선택 및 주요 파일

진입: 개발 활동의 기여자 탭/개요 상위 기여자/협업 node → 기여자 상세 패널 → 주요 파일 선택 → 파일 상세.

패널은 이름·현재 결과·관측 기여 파일 수·파일별 기여 지분·협업자 목록을 보인다. 상위 목록이면 '상위N/총M(제공 시)'을 표시하고 더 보기는 기존 limit 범위에서만 늘린다. 파일 선택 때 부모 기여자 목록/패널 stack을 보존한다. 단일 뒤로로 기여자로, 패널 닫기로 원래 목록으로 복귀한다. 전체 기여자 페이지네이션을 기존 API가 무제한 지원한다고 약속하지 않는다.

### E. 협업 네트워크 및 상위 협업 쌍

진입: 협업 → 전체 metrics와 표시 범위 확인 → 이름 찾기/최소강도/노드 상한 선택 → node 또는 pair 선택 → 관계 상세/기여자 상세.

선택 이웃과 pair 행을 양방향 강조하고 선택 상태를 유지한다. 관계 상세에 A→B, B→A, 공동 수정/리뷰 기여, 전체 PR·리뷰 기반 분모를 보여준다(응답에 있는 필드만). 상위쌍은 전체 snapshot 결과의 순위인지 현재 graph subset인지 명시한다. 현재 API의 top-pairs는 전체 결과이므로 graph filter에 맞춘 순위라고 표시하지 않는다. 보이지 않는 기여자는 이름 검색으로 가져왔다고 꾸미지 않고 표시 상한 증가를 안내한다.

### F. 파일 선택 및 수정 기여자·공동 변경 파일

진입: 파일 → 경로 검색/디렉터리 선택 → 파일 행 → 상세 패널 '수정 기여자' 또는 '공동 변경' → 기여자/관련 파일.

기본 목록은 경로·점검 우선순위·관측 변경수·BF80·공동 변경 support. tree는 폴더 펼치기 보조 뷰다. 공동 변경 탭은 pair 표로 score·함께 변경 횟수·A→B/B→A·단위를 제공한다. '파일 시간순 커밋 이력'은 현재 집계 응답으로 만들 수 없어 보류하고 GitHub 기준 SHA 파일 열기를 제공한다. 파일 관계를 import 관계/미래 영향이라고 부르지 않는다.

### G. 특정 commit 또는 PR AI 리뷰

진입: 저장소 안 AI 리뷰 → PR/커밋 탭(기존 repo 유지) → 대상 선택 → 변경 파일 선택 → 고정 입력 준비 → 미리보기·동의 → 실행 → 결과·근거/피드백.

사용자는 대상 번호/SHA·base/head·선택/분석 가능 파일·제외 이유·실행 위치·모델·키 hint/version·전송 범위·토큰/비용 추정을 확인한다. 모델·입력 변경 시 동의를 초기화한다. 비용이 생길 수 있는 호출은 명시 버튼 뒤에만. 결과는 요약·심각도별 지적·근거 라인·사람 판정으로 구성하며 0건은 무결함 보증이 아니다. 실패/결과 불명은 자동 재실행하지 않는다. 새 실행과 동일 요청 복구(멱등 key 유지)를 구분한다. PR head가 바뀌어도 과거 고정 결과를 현재 코드 결과라고 표시하지 않는다.

로컬 미커밋 변경 리뷰는 '로컬 작업 > 리뷰·제안' 경로를 사용한다. PR/commit 리뷰와 대상·실행 위치가 다르므로 같은 대상 목록으로 합치지 않는다.

### H. API Key 설정 및 변경

진입: 설정 → 모델·API 키 또는 리뷰의 '키 관리' → 제공자·모델 선택 → key 입력/확인·저장/교체 → masked 상태 확인 → 원래 리뷰 복귀.

원격 키는 '현재 계정의 서버 암호화 저장', local cloud key는 '이번 로컬 리뷰의 main 메모리에만 보관'을 명확히 구분한다. 후자는 settings에 영구 저장 버튼을 만들지 않고 해당 리뷰의 일회 입력으로 안내한다. 서버 key 교체/삭제는 기존 작업의 credential version과 취소 영향 안내를 유지한다. key 수정 후 돌아온 미리보기는 최신 상태를 다시 조회하고 동의를 재확인한다. 모델 목록/가격/한도는 서버 registry 응답에서 표시하며 디자인에 고정하지 않는다.

## 6. 디자인 시스템 방향

### 테마·색·위계

정밀한 표·코드 읽기에 적합한 차분한 중립색 기반. 첫 실행 기본은 Windows/system, 사용자가 light/dark/system을 선택하도록 제안한다. 현재 root dark 강제와 remote media-query를 같은 정책으로 통일한다. 테마 선택은 비민감 UI preference이며 API/key 정책을 바꾸지 않는다. 저장 방식은 구현 단계에서 정한다.

| 역할 | Light | Dark |
|---|---|---|
| canvas | `#F5F7FA` | `#11161D` |
| surface | `#FFFFFF` | `#1A222D` |
| raised/hover | `#EDF2F7` | `#253142` |
| primary text | `#172033` | `#E6EDF5` |
| secondary text | `#4B5B70` | `#B0BED0` |
| border | `#CCD5E0` | `#425269` |
| accent/link | `#1D4ED8` | `#8CB7FF` |
| solid primary action bg/text | `#1D4ED8 / #FFFFFF` | `#2563EB / #FFFFFF` |
| success text | `#166534` | `#86EFAC` |
| caution text | `#854D0E` | `#FDE047` |
| error text | `#B91C1C` | `#FDA4AF` |
| focus outline | `#1D4ED8` | `#93C5FD` |

색은 후보 토큰이며 모든 조합의 접근성 통과를 주장하지 않는다. 실제 텍스트 조합은 일반4.5:1, 큰 글자3:1, 조작 경계/포커스3:1을 목표로 측정한다. 점수 높음은 '점검 우선'이며 빨간 결함 확정 배지로 쓰지 않는다. 예비 점수와 유지보수 우선순위를 같은 색 척도/순위로 섞지 않는다.

차트 기본 series 후보는 blue `#2563EB`, teal `#0F766E`, violet `#7C3AED`, orange `#B45309`. dark는 각 계열의 밝은색으로 대체한다. cluster는 범주 팔레트이며 위험 단계가 아니다. 색 외 선 형태·label·선택 테두리·숫자 표로 식별한다.

### 글자·밀도·간격

- 폰트: `Segoe UI, Malgun Gothic, system-ui, sans-serif`, 코드/경로는 `Cascadia Mono, Consolas, monospace`. 새 웹 폰트 의존성 없이 Windows fallback 사용.
- 기본본문/표13~14px, 보조12px, 화면 제목20px/행높이28px, section16px/24px, KPI28px/34px. 11px은 주 데이터에 사용하지 않는다. 숫자는 tabular-nums, 단위/분모 표시.
- 간격 토큰: 4/8/12/16/24/32px. 화면 padding24(작은 창16), panel16, section gap24, label-control gap8. radius6(control)/8(panel), border1px. 큰 그림자·장식 hero를 줄인다.
- control 높이32~36px, 기본 table row36px, 편안한 밀도44px. 버튼 hit area 최소32px 목표. compact row28px는 선택 옵션으로만 제공하고 keyboard focus는 유지한다.
- table: sticky header, 경로 열 최소240px·가변 확대, 수치 우측정렬, row hover/selected 구분. '—'는 결측 사유 접근 가능 설명, 0은 숫자0. 상위N·필터 결과수·수신 범위를 명시한다.
- 차트: 기본 높이240~280px(활동 상세320까지), x축 월·y축 건/명/% 명시. dual/triple axis 혼합보다 공유 x축 small multiples. 데이터 표 토글과 빈 구간 설명 제공.

### 공통 컴포넌트와 상태

| 컴포넌트 | 명세 |
|---|---|
| AppNav / RepoHeader / ContextBar | 현재 메뉴·repo·mode·snapshot·기간·수집/근거 상태, keyboard 탐색 |
| SearchToolbar / FilterChip | 화면 상단 고정, 검색 대상/수신 범위 명시, 초기화 버튼 |
| DataTable / MetricCard | 정렬 방향, 단위, sample, 결측 구분, 상세 열기 버튼 |
| DetailPanel | title/뒤로/닫기 고정, body scroll, opener focus restore, 작은 창 full view |
| AsyncPanel / EmptyState | loading/error/empty/partial/unauthorized/unsupported 구분, 실제 가능한 CTA |
| JobStatus / ProgressPanel | 실제 stage·건수·조회 시각·재시도 시각. 불명 총량은 indeterminate |
| GraphToolbar / PairTable | 검색·fit/zoom/정지, 그래프와 표 선택 동기화, 키보드 대체 |
| ReviewConsent / Findings / KeyStatus | 입력·실행위치·credential 범위·동의/추론/사람 판정 구별 |

전환 피드백은 hover/focus 즉시, 클릭 후 disabled+busy 상태와 live 안내. 새 화면은 heading으로, 상세는 제목/첫 행동으로 포커스 이동. 성공 toast는 일시적 확인에만 쓰고 작업 실패/불명/수집 누락은 지속 상태로 남긴다. 120~180ms 움직임, `prefers-reduced-motion`에서 전환/force animation 감소·정지. skeleton은 내용 공간을 유지하되 실제 값처럼 보이는 가짜 숫자를 쓰지 않는다.

## 7. 범위 밖 의존 기능

| 제안/요청 | 이번 IA에서의 처리 |
|---|---|
| 파일별 시간순 commit 목록 | 현재 API 미확인. 상세는 집계로 한정, 별도 API 필요 작업으로 남김 |
| 사용자 지정 분석 기간 | 서버 매개변수는 있으나 desktop allowlist 미지원. 계약 변경 승인 후 구현 |
| 검색 전체 결과 pagination | 현 요청은 상위20건. 전 페이지를 찾았다고 표시하지 않음 |
| 저장소 자동 연결/일괄 background 감시 | 현재 proof/계정/native 확인·추적 상한 유지, 자동화하지 않음 |
| 로컬 키 영구 저장·서버 키 자동 공유 | 기존 저장 경계 변경 필요. UI 통합과 분리하여 보류 |
| graph layout를 저장소의 실제 조직 구조로 해석 | 지원하지 않음. 관측 관계·표시 부분집합으로 설명 |
