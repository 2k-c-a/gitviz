# 화면별 텍스트 와이어프레임 명세

기준: `c459f29` · 2026-10-29 · **모든 배치는 제안이며 구현하지 않았다.** [현재 화면](project-audit.md) · [정보 구조·토큰](information-architecture.md) · [구현 순서](implementation-plan.md)

`[고정]`은 해당 scroll container 밖, `[스크롤]`은 본문, `[선택]`은 사용자 선택에 따라 등장한다. 기본 shell은 native 창 제목줄, 앱 헤더, 좌측 전역/저장소 메뉴, 결과 context bar, main, 선택 detail, 상태줄이다. 작은 창에서는 상세가 main을 대체한다. 표를 제외한 body 전체 가로 스크롤은 만들지 않는다.

## W01. 저장소 탐색

목적: 이미 분석한 결과를 빨리 열거나 새 GitHub 저장소를 찾아 분석한다. 현재 원격 index/search/myprojects의 선택 목적을 통합한다.

```text
[고정 앱 헤더]  GitViz              작업함(진행 N) | 계정
[nav] 탐색* / 로컬 작업 / 설정
[고정 제목]    저장소 탐색
[고정 탭]      검색 | 최근·내 분석
[고정 입력]    [키워드 또는 https://github.com/owner/repo       ] [검색]
[고정 필터]    정렬[관련도 v]                    표시 범위: 상위20건
[스크롤 목록]  owner/repo · 언어                 [결과 열기]
               설명 / stars·forks·갱신           완료 #결과 / 기간
               owner/another                    [분석 시작]
               설명 / 보조 예비점수ⓘ            결과 없음
[상태줄]       원격 연결 상태 | 로컬 구성 상태
```

- 상단/내비게이션: 전역 탐색 선택. 저장소 미선택이면 하위 분석 메뉴 대신 '저장소 선택 후 사용' 안내를 준다.
- 주요 콘텐츠: 행/가벼운 card 목록. owner/repo가 첫 위계, 예비 점수는 펼침 가능한 보조 근거다. 카드 전체 click과 GitHub 외부 링크를 구분한다.
- 보조 정보: 최근·내 분석 탭은 이름/결과 기간/최근 실행 상태/저장 결과 열기/진행 확인/재분석. local 프로젝트 등록 목록과 섞지 않는다.
- 입력/필터: keyword/URL, 현재 API에서 지원하는 sort만. 결과 검색·정렬 상태와 오류 전 입력을 보존한다. URL은 분석 대상 미리보기 후 시작하며 텍스트 검색과 혼동하지 않게 mode label을 보인다.
- 행동/연결: 결과 열기→W03, 진행 확인/분석 시작→W02. 재분석은 별도 명시 행동. 외부 GitHub는 기존 native 확인을 유지한다. ID 미확정은 재시도, POST fallback 금지.
- 상태: 초기='키워드 또는 URL 입력'과 최근 목록; loading=목록 skeleton+검색 busy; 0건=검색어 수정/URL; 401=계정 연결; 429=재시도 시각; 연결 오류=같은 자리 재시도/설정. 기존 결과 여부 미확정과 결과 없음은 구분한다.

## W02. 분석 진행 상세 패널

목적: 작업 진행을 이해하고 다른 화면에서 돌아와 기존 작업을 계속 확인한다. 작업을 새로 시작하는 화면과 조회 화면을 구별한다.

```text
[패널 고정 header] owner/repo 분석                 [닫기]
[고정 상태]       수집 중 / GitHub 한도 대기 / 결과 저장 확인 중
[스크롤 body]     ● 데이터 수집       커밋1,234 · PR56
                  ○ 기여자 신원 정리
                  ○ 지표 계산
                  ○ 결과 저장
                  마지막 확인 시각 / 서버가 준 재개 시각
                  [수집 범위·상세 정보 펼치기]
[고정 footer]     [나중에 확인]     완료 후 [결과 #42 열기]
```

- 상단/내비게이션: W01 위 패널 또는 저장소 화면에서 열린 진행 패널. 부모 화면과 현재 저장소를 유지한다. 헤더 작업 배지가 재진입점이다.
- 주요 콘텐츠: 서버 stage와 실제 건수. stage를 25/50/75%처럼 시간 진행률로 환산하지 않는다. 총량을 주는 항목만 수량 progress를 제공한다.
- 보조 정보: 관측 기간(요청 계약이 확인한 경우), 시작/마지막 조회, 재시도 대기, 기존 성공 결과 링크. 기술 job ID는 details에 둔다.
- 입력/필터: 없음. 동일 작업 '다시 확인'은 GET 폴링 재개다. stale 교체/실패 재분석은 별도 버튼 및 의미 설명.
- 행동/연결: 닫기=패널/조회 중단, 서버 취소 아님. 현재 분석 API에 없는 임의 취소 버튼은 만들지 않는다. done+snapshot ID 확인 후 W03. 실패 때 마지막 성공 결과 열기.
- 상태: 접수 pending/running/rate_limited/stale/failed/교체됨/done 구분. 네트워크 조회 오류는 작업 실패와 분리한다. 401/404는 무한 재시도하지 않고 계정/접근 확인. 완료된 단계와 수집 partial을 동일 의미로 묶지 않는다.

## W03. 분석 개요 대시보드

목적: 현재 결과의 범위와 중요한 활동·탐색 출발점을 한 화면 상단에서 파악한다.

```text
[고정 헤더]  ← → | owner/repo [원격]      [진행 상태] [재분석]
[nav]        개요* / 개발 활동 / 협업 / 파일 / AI 리뷰 / 분석 이력
[고정 문맥]  결과#42 v3 | 2026-... ~ ... | 수집 부분/근거 제한 [상세]
[스크롤]
  개요
  [구간 커밋] [활성기여자90일] [구간 릴리즈] [버그 수정 분류 비율]
  [월별 커밋 수 bar, 높이240, x=월/y=건]             [개발 활동 열기]
  [점검할 파일 상위5: 경로/상대점수/표본]  [주요 기여자 상위5: 이름/커밋]
  [상위 협업쌍3: A↔B/강도]              [최근 릴리즈5: tag/날짜]
```

- 상단/내비게이션: 결과 선택은 고정 snapshot을 바꾸는 동작. 새 분석 실행과 구분한다. context bar는 조회/수집/근거를 짧은 배지로 분리하고 제한은 클릭 가능 설명으로 연결한다.
- 주요 콘텐츠: 4 KPI는 기간·분모를 함께. 활동은 단일 커밋 bar로 시작해 다른 단위 혼합을 피한다. 하단 파일은 점검 우선순위(결함 확정 아님), 기여자는 관측 commit 순이다.
- 보조 정보: '분석 기준' details의 SHA/기간 종료 제외/계산 버전/수집 coverage·hash. 점수 정의와 메시지 분류 한계를 읽을 수 있다.
- 입력/필터: snapshot 선택만 전역. 활동 표시 구간 조절은 W04에서 제공한다. 재분석 버튼을 필터 옆에 두지 않는다.
- 행동/연결: 파일행→W07, 기여자→W05, pair→W06 관계 상세, '모두 보기'→해당 분석. AI 리뷰는 nav에서 현재 repo 유지→W08.
- 상태: meta 실패=전 화면 범위 오류와 재시도/최신 결과. meta 성공 후 보조 panel 실패=해당 panel만 retry. 관측0건=그 기간 변경 없음/수집 제한 구별. null은 —, 0은0. 자료 부족 상태에서도 사용 가능한 지표는 유지한다.

## W04. 개발 활동 및 기여자 탐색

목적: 시간에 따른 활동 변화와 주요 기여자의 파일 탐색을 분리된 두 탭에서 제공한다.

```text
[고정 문맥] 현재 repo / 결과 / 기간
[고정 title/tabs] 개발 활동         활동* | 기여자
[고정 toolbar] 표시 범위[전체 관측구간 v]    [숫자 표로 보기]
[스크롤 활동]
  월별 커밋 bar(x=월, y=건, 240px)
  월별 활성 기여자 line(x=같은 월, y=명, 180px)
  월별 버그 수정 분류 비율 line(y=0~100%, 180px, 분모 안내)
  커밋유형 horizontal bars(6종, 건수·비율) | 릴리즈 tag/날짜 목록

[기여자 탭 toolbar] [수신 기여자 이름 찾기] [상위20 v] 표시20명
[스크롤 기여자]
  이름 / 구간 커밋 / 순위 / [상세 열기]
  최근16주 활동 heatmap: 행=상위 기여자, 열=주, 셀=관측commit 수
```

- 상단/내비게이션: 공유 shell 유지, 활동과 기여자 탭. 목록과 선택 panel을 함께 사용한다.
- 주요 콘텐츠: 활동 차트는 x축 정렬로 같은 시점 비교, y단위는 각 차트 옆에 항상 표시. 커밋 유형은 작은 도넛 대신 긴 label/건수를 읽기 쉬운 bar/표를 우선한다.
- 보조 정보: active90일 KPI와 월별 활성의 기간 차이, 희소 sample·메시지 규칙 분류 설명. heatmap 주별 tooltip 외 숫자 표 대체 제공.
- 입력/필터: 표시 범위는 현재 snapshot 내부 월 slice이며 재계산 아님. 기여자 검색은 수신 목록 안에서만. API limit와 heatmap 상위100명 제한을 준수, 존재하지 않는 전체 검색으로 광고하지 않는다.
- 행동/연결: 기여자 열기→W05, 릴리즈 외부 링크는 실제 제공 URL이 있을 때만. 월 클릭으로 그 월 commit 전체 목록을 여는 동작은 API가 확인되기 전 제공하지 않는다.
- 상태: 월별 빈 자료/기여자 없음/식별 불가 구분. 히트맵만 실패해도 목록 유지. snapshot의 월별 null→0 변환 경계는 원천 계약 개선 전 UI 단독으로 새로운 결측 판단을 만들지 않는다.

## W05. 기여자 상세 패널

목적: 선택 기여자가 어떤 파일에 얼마나 관여했고 누구와 연결되는지 파악한다.

```text
[고정 panel] [내부 뒤로] 이름 / 연결계정           [닫기]
[고정 문맥] 결과#42 · 관측 기간
[스크롤]
  관측 기여 파일 M개       (개인 성과/코드 품질 평가 아님)
  주요 파일 [수신 경로 찾기]
  경로                         기여 지분       [파일 열기]
  app/...                      55%             >
  [상위N개, 더 보기(한도 내)]
  협업자
  이름         양방향 강도        [기여자 열기]
```

- 상단/내비게이션: opener는 개요/활동/협업/파일 수정자. 내부 back과 앱 back 구분, 닫으면 opener 행 포커스 복귀.
- 주요 콘텐츠: 주요 파일 지분은 해당 파일의 식별된 관측 변경에 대한 기여율이지 기여자 전체 작업의 파일 비중이 아니다. 분모 설명을 열 제목에서 제공한다.
- 보조 정보: 현재 결과 범위와 불완전 신원 연결 주의. 응답에 없는 이메일/프로필 통계는 만들지 않는다.
- 입력/필터: 수신 파일 경로, 기존 limit를 이용한 bounded 더 보기. total이 없는 협업자 목록은 정확한 전체 건수로 표시하지 않는다.
- 행동/연결: 파일→W07, 협업자→같은 패널 stack. 원래 차트·검색·scroll 보존. 사용자가 복수 패널을 무한 중첩하지 않도록 한 panel 안에서 교체한다.
- 상태: 파일/협업자 각 독립 loading/error/empty. 404=이 snapshot의 기여자가 없거나 접근 불가. 늦은 응답은 선택 token 검사 후 폐기한다.

## W06. 협업 네트워크 분석

목적: 사람 간 관측 협업 관계를 그래프와 표로 함께 탐색한다.

```text
[고정 title] 협업
[고정 toolbar] [표시 기여자 찾기] 상위[50/100/200] 최소강도[...] [초기화]
[스크롤 상단] 전체 기여자/엣지/군집/고립 수 | 현재 표시50명·엣지N개
┌ 그래프(main 약65%)                 ┬ 상위 협업쌍(약35%)               ┐
│ node=기여자,크기=commit,색=군집     │ A / B / 양방향강도 / [관계 보기] │
│ 선택 node+이웃 강조                 │ 선택 행과 graph 동기화           │
│ [−][+][맞춤][배치 정지]            │ 키보드 목록 탐색                 │
└────────────────────────────────────┴──────────────────────────────────┘
[선택 detail] A→B / B→A / 공동수정·리뷰 근거 | [A 상세] [B 상세]
```

- 상단/내비게이션: 다른 저장소 분석과 같은 shell/context. 현재 graph 범위와 전체 snapshot metrics 라벨을 분리한다.
- 주요 콘텐츠: 기본 50명, 기존 network API 상한1000 내 단계 증가. 노드 상한 증가는 요청/렌더 성능을 측정하며 제공한다. viewport 약360px 이상을 목표로 하되 낮은 창은 그래프/표 탭으로 전환한다.
- 보조 정보: co-edit는 같은 PR·파일 실제 수정, review 방향, 강도 의미. 고립 기준은 전체 그래프 값과 화면 부분집합의 degree를 구별한다. 선택 시 label을 고정해 hover 의존을 줄인다.
- 입력/필터: 최소강도와 node limit는 기존 endpoint query, search는 표시 노드 내부. 군집 강조는 client 표시 필터이며 전체 통계를 재계산하지 않는다.
- 행동/연결: node→W05, pair→관계 상세, A/B 상세 선택→W05. 방향은 선택 관계에 화살표/정확한 수치를 보여 과밀을 줄인다. 전체 top-pairs에 있으나 현재 graph 밖인 pair는 범위 밖임을 안내하고 상한 증가를 제안한다.
- 상태: nodes0, edges0, 일부 수집, 필터0건을 구별. PR 없음을 '협업 없음'으로 단정하지 않는다. graph 오류에도 pair 표 조회 가능하면 유지. layout 정지·reduced motion·키보드 대체 표 제공.

## W07. 파일 분석과 파일 상세

목적: 파일 찾기 → 점검 근거 확인 → 수정 기여자/공동 변경 후보로 이동한다.

```text
[고정 title/tabs] 파일            파일 목록·계층* | 공동 변경
[고정 toolbar] [파일 경로 검색] [디렉터리] 정렬[점검 우선순위 v] [초기화]
┌ [선택 계층:폴더 목록] ┬ [스크롤:파일 표]                          ┬ [상세 선택]
│ 접기/펼치기           │ 경로 / 점수 / 변경건 / BF80 / 동반support│ 파일명 [×]
│                       │ 긴 경로 열 가변, 숫자 우측, sticky head  │ 전체 경로
└───────────────────────┴─────────────────────────────────────────┴────────────

[공동 변경 탭] 정렬[원 score / IDF(실험)] 최소score[ ] 경로검색[ ]
 A파일 / B파일 / score / 함께변경N / A→B / B→A / 단위 / 표본표시

[상세 panel] [뒤로] 경로                              [닫기]
             결과#42 / SHA / 기간 [GitHub에서 파일 열기]
             요약·점수 근거 | 수정 기여자 | 공동 변경
             [스크롤 탭 내용]
```

- 상단/내비게이션: 파일 목록 우선. 현재 원형 tree를 계층 보조 뷰로 제공할 수 있지만 초기 전체 SVG 펼침은 기본 동작으로 하지 않는다. tree 자체는 공동 변경 그래프로 이름 붙이지 않는다.
- 주요 콘텐츠: 파일 표는 tree 응답의 존재 필드만 매핑. 점수가 없으면 —/사유, 표본 부족 badge. 정렬은 결측 뒤/동률 안정 정렬을 유지한다. 경로와 상세 버튼을 분리해 링크 클릭 위치에 따라 전혀 다른 곳으로 가는 혼동을 줄인다.
- 상세 요약: 상대 점수와 change frequency/churn/bugfix rank 근거, 관측 변경수·low support. BF80·기여 분산은 별도 설명 지표.
- 상세 수정자: 이름/지분 horizontal bar+숫자/가능한 관측 건수, 미식별 한계. 사람 click→W05. 응답에 count가 없으면 지분을 임의 정수 건수로 역산하지 않는다.
- 상세 공동 변경: 상대경로/함께변경N/선택→상대 비율/상대→선택/score, PR·commit fallback 이유. 분모 제공 필드를 label에 매핑한다. 상대 파일→같은 panel stack. IDF 정렬은 확률/강함 임계값과 분리한다.
- 보조 정보: 현 API에는 per-file 시간순 commit 이력이 없으므로 가짜 '변경 이력' 탭을 만들지 않는다. GitHub 링크는 snapshot target SHA를 사용하고 접근 불가를 처리한다.
- 입력/필터: path query, directory, 기존 지표 sort, coupling min_score/sort_by. 수신 부분목록 필터와 서버 전체 정렬 뒤 limit을 구별한다. 전체 tree row 렌더 비용이 크면 client 페이지 분할/점진 렌더를 먼저 검토한다.
- 상태: tree 초기 loading; 목록0/검색0/공동변경 후보0/기여자 미식별/표본부족을 구분. 해당 snapshot에 없는 file404는 패널 오류, 부모 목록 유지. 다른 파일로 빠르게 바꿀 때 이전 응답으로 덮지 않는다.

## W08. AI 코드 리뷰

목적: 대상 변경을 고정하고 전송 범위를 이해한 뒤 결과 근거를 검토한다. 키 설정은 별도 화면으로 이동하되 돌아올 경로를 보존한다.

```text
[고정 header] repo / AI 리뷰              모델[응답 기반] 키상태 [관리]
[고정 tabs] 새 리뷰 | 실행·결과 | 이력
[고정 steps] ①대상  ②파일  ③미리보기·동의  ④실행·결과
대상:
  [PR* | 커밋] [PR상태 v]   번호·제목·SHA·시각 / [선택] / [더 보기]
파일:
  [경로 필터] 선택N / 전체M / 제외K
  체크 / 경로 / 추가·삭제 / 분석가능 여부 / 제외 이유
  [선택 파일 diff 미리보기]                         [고정 입력 준비]
미리보기:
  대상 base/head · 파일 목록·제외 · 코드 미리보기
  실행위치/목적지 · 모델 · 키hint/version · 토큰/비용 추정
  [ ] 고정 입력·전송/실행 조건 확인                  [동의 후 실행]
결과:
  상태/현재 단계/추정·확정 비용 구분
  요약 | 지적 목록(심각도·경로·사람판정) | 선택 지적 근거 코드
```

- 상단/내비게이션: current repo 표시. 원격 AI와 local workspace 리뷰는 같은 대상 탭으로 합치지 않는다. 결과 링크/뒤로 이동은 기존 URL input/job 규칙을 보존한다.
- 주요 콘텐츠: 대상·파일 단계는 목록, preview는 2열(전송 명세/코드, 좁은 창 세로). 결과는 왼쪽 finding 목록, 오른쪽 고정 code 근거. 원격 작업을 파일 적용 버튼과 이어 자동 실행하지 않는다.
- 보조 정보: coverage=전체 변경/선택/실제 분석, 제외 이유, stale PR head, 사람이 검증하지 않았음. 취소는 전송 회수 아님. 공유 결과는 읽기 전용과 원문 접근 경계를 표시한다.
- 입력/필터: PR 상태/PR·커밋 선택/전체40자 SHA, 파일 path/checkbox, 허용 provider profile, 명시 동의, 사람판정/메모. 지원하지 않는 임의 모델명을 text로 받아 main에 전달하지 않는다.
- 행동/연결: key관리→W10(return route), 대상/모델 변경→preview 재조회·동의 해제, 결과 근거 위치→고정 코드. 새 호출은 버튼, 동일 접수 불명 복구는 같은 멱등 intent 유지. 결과 이력 선택은 기존 job/result GET.
- 상태: AI disabled/권한 필요/키 없음/선택0/비지원 파일/입력 준비중/만료/비용한도/429/결과불명/저장실패/0지적을 분리한다. 0지적='보고된 지적0건·미검증', 실패='결함 없음' 아님. 재실행은 동의/비용 재확인.

## W09. 분석 이력·비교

목적: 과거 결과를 정확히 열고 비교 가능한 두 시점을 선택한다.

```text
[고정 title] 분석 이력       [현재 결과로 돌아가기]
[스크롤 표] 이전선택 / 이후선택 / 결과ID / 분석시각 / 관측기간 / 버전 / SHA / [열기]
             더 보기(기존 before_id cursor)
[고정 선택요약] 이전#40 → 이후#42                    [비교]
[스크롤 비교] 비교 가능조건/기간 차이 안내
              공통파일/추가/제외 / 지표 이전·이후·차이 표
```

- 상단/내비게이션: 원격 snapshot 이력이며 local '전후 고정 입력·실측 비교'와 이름·기준을 구별한다.
- 주요 콘텐츠: 현재 결과 행 표시, 표 sticky head, 결과 열기와 비교 선택을 다른 버튼/라디오로 구성. 비교 표는 값 존재 여부와 상대 점수 차이 설명을 유지한다.
- 보조 정보: 동일 repo·계산 버전 조건, 기간 차이, rename은 제외+추가라는 한계. '점수 하락=품질 향상' 결론을 자동 생성하지 않는다.
- 입력/필터: 이전/이후 snapshot selector와 기존 pagination. 제공되지 않는 임의 diff 계산은 하지 않는다.
- 행동/연결: 열기→W03의 해당 ID, 파일행 상세→해당 결과 기준 W07(이전/이후 중 무엇인지 명시). 가능한지 API 응답을 확인한 뒤 연결한다.
- 상태: 결과0=분석 시작, 1개=열기 가능/두 결과 비교 불가, 계산 버전 불일치=비교 제한 이유, 일부 요청 오류=목록 유지·비교만 retry.

## W10. 설정·API 키 관리

목적: 계정/키/실행 환경을 이해하고 안전하게 바꾼 뒤 원래 작업으로 돌아간다.

```text
[고정 title] 설정                  [리뷰로 돌아가기(진입 시)]
[고정 탭] 계정 | 모델·API 키* | 로컬 환경 | 앱·진단
[스크롤]
  원격 리뷰: 현재 계정의 서버 저장 키
  제공자 [허용 목록] / 모델 [registry 목록]
  상태: 등록됨·hint·버전 / 사용·예약·한도
  [새 키 password]                 [확인·저장/교체] [삭제]
  교체·삭제 시 기존 작업에 미치는 영향
  로컬 작업 cloud 리뷰: 일회 입력, 저장하지 않음 [해당 리뷰로 이동]
  로컬 모델: 실행위치·연결 조건, key 불필요
```

- 상단/내비게이션: 전역 메뉴에서 언제든 진입. return target은 허용된 앱 route만이며 key를 포함하지 않는다.
- 주요 콘텐츠: provider 별 key 상태와 허용 profile 선택. 원격 키/일회 입력을 별도 card로 구분한다. 키 원문 재조회/복사 기능은 제공하지 않는다.
- 보조 정보: server storage, 암호화·사용 계정, cost/reserved 구분, 실제 local 실행 위치. 서버 origin은 배포 설정이므로 arbitrary URL 편집 기능을 새로 추가하지 않는다.
- 입력/필터: password 새 키, 기존 허용 모델, theme system/light/dark(향후 UI preference), 기존 editor/local project settings. 키를 다른 설정 저장과 묶어 무의식적으로 제출하지 않는다.
- 행동/연결: 명시 저장/교체/삭제와 성공 후 masked 확인. 삭제 영향은 실행 중 작업과 서버 응답 기준. 복귀 후 preview 재검증. 모델 설치·외부 명령은 설정 화면 표시만으로 자동 실행하지 않는다.
- 상태: key미등록/유효성 거절/모델불가/429/검증 연결실패/저장실패/AI disabled 구분. 실패에 key원문이 섞이지 않게 하고 기존 등록 상태는 성공 확인 전 유지한다.

## W11. 로컬 작업·알림 보존 화면

목적: 기존 workspace 기능을 목적별로 찾게 하면서 읽기/전송/쓰기/명령 실행 경계를 유지한다.

```text
[고정 header] 로컬 프로젝트[선택 v] [로컬] · 경로요약/연결원격 이름
[nav] 프로젝트·변경* / 리뷰·제안 / 영향·검증 / 알림
프로젝트·변경:
  [폴더등록] [Git새로고침] → 상태/branch/최근commit
  파일 체크 목록 | diff 미리보기 → [선택변경 고정 캡처]
리뷰·제안:
  고정입력 선택 → preview/동의 → local·허용cloud 리뷰
  결과/제안 diff → 별도 native 승인 → 적용·복구
영향·검증:
  고정입력 정적근거 | 도구탐지·명령계획 → 승인 실행/출력 → 전후실측
알림:
  프로젝트/종류/심각도/읽음 필터 → 알림목록 | 선택대상 요약
```

- 상단/내비게이션: remote repo와 local project를 구별. 연결은 이름으로 선택→proof/native 확인. 연결 정보가 없으면 원격 분석 tab을 local 데이터로 채우지 않는다.
- 주요/보조 콘텐츠: 각 하위 뷰는 원래 workspace의 동일 기능·계약 재배치다. recentLimit·에디터 선택은 프로젝트 설정으로 이동한다. 복구 필요 항목은 리뷰·제안 상단에 지속 배치하고 숨기지 않는다.
- 입력/행동: 기존 capture untracked 선택·generation·제안 승인·검증 명령 계획을 유지. 불필요한 기술 입력을 기본 흐름에서 줄여도 새 실행 generation 의미와 비용 확인은 남긴다. 알림 click은 조회/이동만 한다.
- 상세 연결: 알림→정확한 project+run/proposal/analysis 대상, 제안→고정 diff, 원격 연결→현재 권한을 확인한 분석 결과. 삭제·만료는 복구 오류와 구별한다.
- 상태: 프로젝트 미선택/agent미준비/이동됨/접근불가/명령미탐지/결과불명/취소요청/적용복구필요/미측정 비교를 각각 처리. agent 장애여도 원격 탐색 가능한 경우 그 행동은 유지한다.

## 공통 상태·포커스 검수표

| 상황 | 항상 보일 것 | 행동 |
|---|---|---|
| 최초 로드 | 실제 loading과 기준 문맥 | 뒤로/다른 화면 탐색 가능 |
| 데이터 없음 | 기간·대상·필터 중 어느 범위인지 | 필터 해제/대상 선택/분석 시작 중 적합한 것 |
| 부분 수집/표본 부족 | 수치와 제한을 함께 | 수집 상세/기존 결과/명시 재분석 |
| 401/권한 불가 | 판단 가능한 범위의 메시지 | 로그인/선택 복귀, 다른 사용자 자료 노출 금지 |
| 통신 오류 | 조회 실패와 실제 작업 실패 구별 | GET 재확인, 자동 POST 재실행 금지 |
| 상세 선택 변경 | 새 선택 title+loading | 이전 응답 무시, 닫으면 opener로 |
| 작은 창/확대 | 주 행동과 닫기/뒤로 | 표 안 scroll, detail 전체 뷰, focus 가림 방지 |

구체 색·폰트·간격은 [디자인 방향](information-architecture.md)의 토큰을 적용한다. 화면마다 별도 arbitrary palette를 만들지 않는다.
