## 1. 설계 원칙

1. **작업 흐름이 구조다.** 화면 목록은 사용자가 하는 일의 순서와 같다.
2. **한 화면에 한 가지 일.** 긴 스크롤 대신 프로젝트 안의 탭으로 나눈다.
3. **다음 행동을 앱이 말한다.** 프로젝트 상태에 따라 "지금 할 일"을 하나만 크게 제시한다.
4. **위험을 먼저 보여 준다.** 모든 행동 버튼에 위험 등급(읽기 / 전송 / 파일 변경 / 명령 실행)을 붙인다.
5. **근거 종류를 항상 구분한다.** 실측, 정적 분석, 과거 통계, AI 추정을 섞지 않는 원칙을 시각 언어로 만든다.
6. **로그인과 AI는 선택 기능이다.** 둘 없이도 Git 상태, 영향 범위, 검증 실행은 쓸 수 있다고 알려 준다.
7. 안내문은 **그 순간에만, 한 줄로.** 긴 설명은 "자세히"로 접는다.

## 2. 정보 구조

```text
GitViz Workspace
├─ 시작하기           프로젝트 0개일 때만 홈을 대체
├─ 프로젝트           목록 (전역)
│   └─ [프로젝트]     선택하면 프로젝트 작업공간 (아래 탭)
│        ├─ 개요          Git 상태 + 다음 할 일
│        ├─ 변경          점검 대상 담기
│        ├─ AI 점검       전송 확인 → 실행 → 결과·이력
│        ├─ 개선 제안     검토 → 승인 적용 → 복구
│        ├─ 테스트·린트   도구 탐지 → 승인 실행 → 출력
│        ├─ 전후 비교
│        └─ 영향 범위
├─ 알림               전역 (읽지 않음 배지)
├─ 계정·연결          로그인, 프로젝트-서버 저장소 연결
├─ 설정               에디터, AI 모델, 진단, 테마, 업데이트 상태
└─ 웹 분석 열기       GitHub 검색·원격 분석·AI 리뷰 (기존 링크)
```

탭 순서는 작업 순서와 같다. 선행 조건이 있는 탭에는 이유를 보여 준다(예: "AI 점검 — 먼저 변경을 담으세요"). 말없이 비활성으로 두지 않는다.

### 영역 정의

- **상단 영역 (고정):** OS 제목줄에 `프로젝트명 — 브랜치`를 표시한다. 그 아래 네이티브 메뉴. 프로젝트 헤더에는 프로젝트 전환 드롭다운, 브랜치·변경 수 칩, 경로, 계정 칩을 둔다.
- **내비게이션 영역 (고정):** 좌측 레일은 208px 확장 / 56px 아이콘 / 600~720px에서는 오버레이. 그 아래 프로젝트 탭은 가로 탭이며 좁으면 드롭다운으로 접는다.
- **주요 콘텐츠 영역 (스크롤):** 화면 하나당 하나의 스크롤 컨테이너만 둔다. 본문 전체 스크롤과 패널 내부 스크롤이 겹치지 않게 한다.
- **보조 정보 영역 (우측 인스펙터, 접힘 가능):** 1280px 이상에서 상시 표시, 900px 이하에서는 서랍(drawer). 선택 항목의 상세, 전송 요약, 근거를 담는다.
- **상태 표시줄 (고정):** 에이전트 상태, 원격 연결, 실행 중 작업 수, 앱 버전. 현재 맨 위의 "로컬 구성 요소를 확인하고 있습니다"와 "구성 요소 상태 확인"을 여기로 옮긴다. 정상일 때는 조용하고 문제일 때만 눈에 띈다.

### 창 크기 대응

| 폭 | 레이아웃 |
| --- | --- |
| 600 (최소, 600×400) | 레일은 오버레이, 탭은 드롭다운, 인스펙터는 서랍, 상태 표시줄은 아이콘만. 고정 헤더는 약 64px 이하로 줄인다(경로·충돌 칩·계정 이름 숨김). 목업에서 헤더가 110px을 차지해 본문이 거의 남지 않는 것을 확인하고 정한 규칙이다 |
| 900 (기본) | 56px 레일 + 본문, 인스펙터는 서랍 |
| 1280 이상 | 208px 레일 + 본문 + 인스펙터 상시 표시 |

### Windows 사용 특성 반영

- **메뉴:** 파일 > 프로젝트 폴더 등록(`Ctrl+O`), 최근 프로젝트 / 보기 > 레일 접기(`Ctrl+B`), 인스펙터, 테마 / 프로젝트 > 새로고침(`F5`), 편집기에서 열기 / 도움말 > 시작하기 다시 보기, 진단 정보 저장. 메뉴 항목은 화면 버튼의 별칭이며 메뉴에만 있는 기능은 없다.
- **단축키:** `Ctrl+K` 명령 팔레트(프로젝트 전환, 탭 이동, 동작 검색), `Ctrl+1`~`7` 탭 이동, `Esc` 서랍·모달 닫기, `Alt`로 메뉴 열기.
- **폴더 드래그앤드롭:** 창에 폴더를 끌어다 놓으면 등록 흐름이 시작된다.
- **네이티브 대화상자:** 폴더 선택, 파일 적용 승인, 명령 실행 승인은 현재처럼 OS 네이티브 확인창을 쓴다. 앱 안 화면은 "무엇을 승인하게 되는지" 미리 보여 주고 네이티브 창이 최종 확인한다.
- **창 상태:** 크기·위치 복원(이미 있음), 다중 모니터와 100~200% DPI에서 깨지지 않게 상대 단위를 쓴다. 고대비 모드(forced-colors)에서도 경계선과 배지가 유지되어야 한다.
- **작업표시줄 배지·점프 목록(최근 프로젝트):** 후보로만 둔다. 구현 가능 여부는 확인하지 않았다.

## 4. 화면별 설계

각 화면은 기본 창(900×640) 기준이다. 와이어프레임의 오른쪽 경계선은 한글 폭 때문에 생략했다.

### S0. 시작하기 (등록된 프로젝트가 없을 때의 홈)

```text
┌ 시작하기
│ GitViz Workspace는 내 PC의 Git 프로젝트를 점검하는 도구입니다.
│ 코드는 기본적으로 내 PC 밖으로 나가지 않습니다.
│
│ ① 프로젝트 폴더 등록         [ 폴더 선택… ]   또는 폴더를 여기로 끌어놓기
│ ② 변경 확인                  (등록하면 자동으로 표시됩니다)
│ ③ AI 점검 (선택)             로컬 모델: 확인 안 됨   [ 상태 확인 ]
│ ④ 서버 연결 (선택)           로그인 안 됨            [ 계정·연결 ]
│
│ 이것만으로도 됩니다: Git 상태 · 영향 범위 · 테스트·린트 실행
└ 개인정보·전송 범위 자세히 ▸
```

- **목적:** 3분 안에 첫 결과(Git 상태)를 보게 한다.
- **상단:** 앱 이름과 계정 칩("로그인 안 됨 · 선택 사항").
- **내비게이션:** 레일은 프로젝트·알림·계정·설정만 보여 주고 프로젝트 탭은 아직 없다.
- **콘텐츠:** 단계 체크리스트 4개. 선택 단계는 "선택"을 표시한다.
- **보조 정보:** 우측에 "내 코드는 어디로 가나요?" 3줄 요약(기본: 전송 없음, 로컬 모델은 이 PC에서만, 클라우드는 동의한 바이트만).
- **버튼:** `폴더 선택…`(읽기), `상태 확인`(읽기), `계정·연결`.
- **입력:** 폴더 선택과 드롭만 있다.
- **표시 방식:** 체크리스트 행마다 완료 여부를 아이콘+텍스트로 표시한다.
- **상세 연결:** 폴더 등록 → S2, 로컬 모델 확인 → 설정 > AI, 계정 → S10.
- **로딩:** 상태 줄에 "구성 요소 확인 중…", ③④ 행만 스켈레톤.
- **오류:** 에이전트를 시작하지 못하면 최상단 배너에 원인 한 줄, `다시 확인`, `진단 정보 저장`.
- **빈 상태:** 이 화면 자체가 빈 상태의 해법이다.

### S1. 프로젝트 목록

```text
┌ 프로젝트 (3)                                   [ 폴더 등록 ]  Ctrl+O
│ 🔍 이름·경로 검색
│ 이름       브랜치   변경  마지막 점검     원격 연결
│ my-repo    main      7    2시간 전        연결됨(#12)    ⋯
│ api-server dev       0    —               연결 없음      ⋯
│ old-tool   —         —    ⚠ 위치를 찾을 수 없음  [ 다시 연결 ]
└ 더 보기
```

- **목적:** 프로젝트 선택·등록·해제.
- **상단:** 제목과 `폴더 등록`.
- **콘텐츠:** 표. 이름, 경로(툴팁), 브랜치, 변경 수, 마지막 점검, 원격 연결 상태. 헤더 행은 고정, 목록은 스크롤.
- **보조 정보:** 행을 선택하면 인스펙터에 경로, 등록일, 기본 에디터, 최근 활동.
- **버튼:** 행 클릭은 열기, `⋯` 메뉴는 등록 해제(확인 필요)·경로 복사·탐색기에서 보기.
- **입력:** 검색, 정렬.
- **상세 연결:** 행 → 프로젝트 작업공간(개요).
- **로딩:** 스켈레톤 행 3개.
- **오류:** 위치 변경·삭제·접근 거부는 해당 행에 인라인 표시하고 `다시 연결`로 복구. 목록 자체 실패는 `다시 시도`.
- **빈 상태:** S0으로 대체.

### S2. 프로젝트 개요

```text
┌ [프로젝트 헤더 · 탭 (개요 선택)]
├ 지금 할 일
│  변경 7개가 있습니다. 점검할 파일을 고르세요.        [ 변경 보기 → ]
├ Git 상태                               ┌ 인스펙터
│  main @ a1b2c3d4e5f6                   │ 경로, 에디터(VS Code)
│  Staged 2 · Unstaged 4 · Untracked 1   │ 원격 연결: 없음
│  충돌 0                                │ [ 편집기에서 열기 ]
├ 최근 커밋 (20)                          └
│  a1b2c3d4  fix: …   홍길동   2시간 전
├ 최근 활동
│  AI 점검 완료(지적 3) · 테스트 실패 1 · 제안 적용됨
└ 제한 사항 ▸ (submodule 내부 상태는 펼치지 않습니다 외 2건)
```

- **목적:** 프로젝트 현황과 다음 행동을 한눈에 본다.
- **상단:** 프로젝트 헤더와 탭(공통).
- **콘텐츠:** 위에서부터 "지금 할 일", Git 상태 요약, 최근 커밋, 최근 활동. "지금 할 일"은 규칙으로 정한다. 복구 필요 항목이 있으면 항상 최우선, 변경이 없으면 "변경이 없습니다. 새로고침하거나 다른 브랜치를 확인하세요.", 변경이 있으면 "변경 보기", 점검 결과가 있으면 "결과 확인".
- **보조 정보:** 에디터 열기, 원격 연결 상태, `최근 커밋 수` 설정(현재는 본문에 섞여 있으나 인스펙터로 이동).
- **버튼:** `새로고침`(`F5`, 읽기), `편집기에서 열기`, `변경 보기`.
- **입력:** 최근 커밋 수(1~100).
- **표시 방식:** 상태 수치는 칩+숫자. 파일 목록은 S3에 있으므로 여기서는 수만. 커밋은 SHA(고정폭 12자), 제목, 작성자, 상대 시간.
- **상세 연결:** 수치 칩 → S3(해당 필터 적용), 활동 항목 → 해당 탭의 해당 기록, 커밋 → 복사/편집기.
- **로딩:** 섹션별 스켈레톤. 전체를 막지 않는다.
- **오류:** `CHANGESET_TOO_LARGE`는 해결 행동을 문장으로 안내(현재 `statusError`가 이미 함). 링크·junction·config include 같은 제한 코드는 사람말로 바꿔 "제한 사항"에 모은다.
- **빈 상태:** 초기 커밋이 없으면 "아직 커밋이 없습니다. 변경은 untracked로 표시됩니다."

### S3. 변경 (점검 대상 담기)

```text
┌ 변경    🔍 파일 필터   [Staged ▾]
├──────────────────────────┬─────────────────────────────────────────
│ ☐ 전체 선택 (7)          │ src/app.py                 (읽기 전용 diff)
│ Staged (2)               │ @@ -10,6 +10,8 @@
│  ☑ M  src/app.py         │ - old line
│  ☑ A  src/util.py        │ + new line
│ Unstaged (4)             │
│  ☑ M  README.md          │
│  ☐ M  assets/logo.png    │   ⓘ 바이너리: 담을 수 없음
│ Untracked (1)            │
│  ☐ ?  notes.txt          │
├──────────────────────────┴─────────────────────────────────────────
│ [고정 하단 액션바] 3개 선택 · 12 KB · 제외 예정 1  [ 점검 대상으로 담기 ]
└
```

- **목적:** 점검할 변경을 고르고 불변 스냅샷으로 담는다.
- **콘텐츠:** 2분할. 왼쪽은 파일 목록(체크박스, 섹션별 접힘), 오른쪽은 선택 파일의 읽기 전용 diff. 각각 독립 스크롤.
- **보조 정보:** diff 위에 제외 사유 배지. 바이너리, 큰 파일, 비밀 의심은 "담을 수 없음 — 이유".
- **버튼:** `점검 대상으로 담기`(읽기, 로컬 저장만), `새로고침`. 담은 뒤 결과 카드에 `AI 점검 시작`, `테스트·린트`, `영향 범위`, `전후 비교의 이전 기준으로 사용`.
- **입력:** 파일 체크박스, 필터 텍스트, 섹션 필터. 현재의 "선택한 untracked 포함" 체크는 untracked 행을 직접 체크하는 방식으로 대체.
- **표시 방식:** 상태 문자(M/A/D/?)는 문자와 아이콘을 함께. 이름 변경은 `old → new`.
- **상세 연결:** 파일 → 오른쪽 diff, 담은 결과 → 스냅샷 상세(포함/제외 목록).
- **로딩:** 목록 스켈레톤, diff는 선택 시 로드.
- **오류:** 파일 읽기 실패는 행 단위로 표시. 담기 실패는 액션바에 인라인으로 원인과 `다시 시도`.
- **빈 상태:** "변경된 파일이 없습니다. 파일을 수정하면 여기에 나타납니다."

### S4. AI 점검

```text
┌ AI 점검       [ 새 점검 ]  [ 이력 ]
├ 단계: ①대상  ②모델·목적  ③전송 확인  ④결과
├────────────────────────────────────────┬──────────────────────────
│ ② 모델·목적                             │ 보낼 내용 (항상 표시)
│  종류  (•) 코드 리뷰  ( ) 작은 개선 제안  │  대상: 스냅샷 #4 · 3파일
│  모델  [ 이 PC의 Ollama (로컬) ▾ ]       │  목적지: 127.0.0.1 (이 PC)
│        ⓘ 이 PC에서만 처리됩니다           │  크기: 12 KB
│  (클라우드 모델 선택 시)                  │  비용 추정: $0
│  API 키 [••••••]  이번 동의 동안만 보관   │  [ 전송 내용 보기 ]
│  목적  [ 버그·보안·성능·품질 검토      ]  │
│  ▸ 고급: 다시 실행 번호                   │
│                    [ 다음: 전송 확인 → ]  │
└────────────────────────────────────────┴──────────────────────────
```

- **목적:** 담은 변경을 AI에게 점검시킨다. 무엇이 어디로 가는지 확인하고 동의한 뒤에만 실행한다.
- **내비게이션:** 탭 아래 4단계 스텝 표시줄. 이전 단계로는 자유롭게 돌아간다.
- **콘텐츠:** ①대상: 스냅샷 선택(없으면 S3으로 안내). ②모델·목적: 위 와이어프레임. ③전송 확인: 미리보기 바이트 뷰어, 동의 체크박스, `동의하고 시작`. 현재 있는 두 번째 체크박스(중복 비용 확인)는 "다시 실행 번호"를 1보다 크게 바꿨을 때만 나타난다. ④결과: 아래.
- **보조 정보:** "보낼 내용" 요약 패널을 모든 단계에 고정 표시.
- **버튼:** `다음`/`이전`(읽기), `전송 내용 보기`(읽기), `동의하고 시작`(**전송**), `취소 요청`(실행 중 고정 표시).
- **입력:** 종류, 모델, API 키(클라우드 선택 시에만 나타남), 목적(최대 1000자), 고급 항목.
- **④ 결과의 표시 방식:** 2분할. 왼쪽은 지적 목록(심각도·위치·한 줄 요약), 오른쪽은 선택한 지적의 설명, 근거 인용(코드 발췌), 직접 판정 버튼 `맞음 / 오탐 / 보류`. 모든 지적에 `AI` 배지.
- **상세 연결:** 지적 → 해당 파일의 diff 위치, `편집기에서 열기`(파일:줄), 개선 제안 종류의 결과 → S5.
- **로딩/진행:** 실행 중에는 경과 시간과 `취소 요청`. 진행률을 모르면 가짜 퍼센트를 만들지 않는다.
- **오류:** 실패, 취소, **결과 불명**을 각각 다른 문구로. 결과 불명은 "응답을 확인하지 못했습니다. 자동으로 다시 보내지 않습니다. 필요하면 새로 시작하세요." + `새 점검`. 오류 코드는 접어 둔다.
- **빈 상태:** 지적 0건은 "AI가 지적한 항목이 없습니다. 결함이 없다는 뜻은 아닙니다." 이력이 없으면 "아직 점검한 적이 없습니다."

### S5. 개선 제안

```text
┌ 개선 제안   ⚠ 복구가 필요한 항목 1건 [ 복구 목록 ]   ← 있을 때만, 고정 배너
├──────────────────────┬──────────────────────────────────────────
│ 제안 목록            │ 제안 #3 · 상태: 검토 대기      [AI]
│ #3 검토 대기         │ 변경 파일 2개 · 원본 확인됨
│ #2 적용됨            │ ┌ diff ─────────────────────────────
│ #1 거절              │ └──────────────────────────────────
│                      │ 적용하면: 파일 2개를 수정하고 백업을 만듭니다.
│                      │ index·commit·push는 건드리지 않습니다.
│                      │ [ 거절 ]  [ 다시 요청 ]  [ 승인하고 적용… ] (파일 변경)
└──────────────────────┴──────────────────────────────────────────
```

- **목적:** AI가 만든 개선안을 검토하고 명시 승인 후에만 파일에 적용한다.
- **콘텐츠:** 목록 + 상세 2분할. 상세에는 상태, diff, 영향 파일, "적용하면 일어나는 일"을 문장으로.
- **보조 정보:** 원본 해시 일치 여부, 백업 위치, 적용 기록.
- **버튼:** `승인하고 적용…`(**파일 변경**, 네이티브 확인과 일회 승인), `거절`, `다시 요청`, 복구 목록의 `복구…`(**파일 변경**).
- **입력:** 상태 필터. 다시 요청할 때 목적 텍스트.
- **상세 연결:** 파일 → S3 diff, 원래 점검 → S4 결과.
- **로딩/오류:** 적용은 단계별 진행(백업 → 게시 → 확인)을 표시. 중단되면 상태를 "복구 필요"로 바꾸고 상단 배너를 고정. 다른 도구가 파일을 바꿨다면 "덮어쓰지 않았습니다 — 충돌 파일 목록".
- **빈 상태:** "제안이 없습니다. AI 점검에서 '작은 개선 제안'을 선택해 만들 수 있습니다." + `AI 점검으로 이동`.

### S6. 테스트·린트

```text
┌ 테스트·린트      프로젝트 신뢰: ⚠ 아직 신뢰하지 않음 [ 신뢰하기… ]
├ 감지된 작업 (package.json, pytest.ini 기반)
│  npm test            작업 폴더 .        [ 실행… ] (명령 실행)
│  eslint .            작업 폴더 .        [ 실행… ] (명령 실행)
│  ▸ 고급: 작업 폴더 · 패키지 관리자
│  ⓘ 실행되는 코드는 내 Windows 계정 권한으로 파일·네트워크에 접근합니다.
├ 출력 (고정 높이, 내부 스크롤)                   [ 취소 ]
│  > npm test …
│ 결과: 실패(종료 코드 1) · 진단 3건 · 출력 잘림 없음
└ 진단: src/app.py:12  E501 …   [ 편집기에서 열기 ]
```

- **목적:** 프로젝트의 테스트·린트 명령을 감지해 승인 후 실행한다.
- **콘텐츠:** 작업 목록, 출력 뷰어, 진단 목록.
- **보조 정보:** 신뢰 상태, 마지막 실행 기록.
- **버튼:** `다시 감지`(읽기), `실행…`(**명령 실행**, 계획별 네이티브 확인), `신뢰하기…`, `취소`(실행 중 고정), `편집기 설정`.
- **입력:** 작업 폴더와 패키지 관리자는 기본값("프로젝트 루트", "lock 파일 기준")으로 숨기고 "고급"에서만 노출.
- **표시 방식:** 출력은 고정폭 글꼴, 오류 줄은 아이콘. 상한에서 잘렸으면 "출력이 잘렸습니다"를 명시.
- **상세 연결:** 진단 → `파일:줄`로 외부 에디터 열기, 기록 → 전후 비교의 입력.
- **로딩:** 감지 중 스켈레톤, 실행 중 라이브 로그와 경과 시간.
- **오류:** 에디터 미설치·경로 오류는 설정으로 안내. 실행 실패는 종료 코드와 마지막 출력.
- **빈 상태:** "실행할 수 있는 테스트·린트 설정을 찾지 못했습니다. 감지하는 파일: package.json 등."

### S7. 전후 비교

```text
┌ 전후 비교
│ 이전 [ 스냅샷 #3 ▾ ]  →  이후 [ 스냅샷 #4 ▾ ]   ☐ 개선 제안 #3과 연결
│ 준비 상태  ✔ 이전 검증 기록 있음   ✖ 이후 검증 기록 없음 [ 테스트·린트로 이동 ]
│                                                    [ 실측 비교 ]
├ 변경 규모      파일 3→2   줄 +40/−12 → +18/−5
├ 검증 결과      테스트 통과 12→14  [실측]    린트 오류 5→3  [실측]
└ 판정: 비교 불가 — 이전·이후의 실행 환경이 다름(Node 20 ↔ 22)
```

- **목적:** 개선 전후를 **측정값**으로 비교한다.
- **콘텐츠:** 위쪽에 선택기와 "준비 상태" 체크리스트, 아래에 비교 결과 표.
- **버튼:** `실측 비교`(읽기). 체크리스트의 미충족 항목은 해당 탭으로 가는 링크.
- **표시 방식:** 각 수치에 `실측` 배지. 판정은 개선 / 동일 / 악화 / **비교 불가(이유)** 네 가지이며 근거 없는 "개선"은 쓰지 않는다.
- **로딩/오류:** 계산 중 스켈레톤, 실패는 `다시 시도`.
- **빈 상태:** 스냅샷이 2개 미만이면 "비교하려면 점검 대상이 2개 이상 필요합니다" + `변경 보기`.

### S8. 영향 범위

```text
┌ 영향 범위   대상 [ 스냅샷 #4 ▾ ]            [ 분석 ]
│ [ 정적 참조 (25) ]  [ 함께 바뀐 이력 ]  [ AI 추정 ]    ← 탭, 섞어 보여주지 않음
├────────────────────────────┬────────────────────────────────────
│ 변경 파일 → 참조하는 곳      │ 선택 항목 상세
│ src/auth.py                │  참조: src/api.py:34 (import)
│   ├ src/api.py  [정적]     │  ⓘ 동적 호출·외부 모듈은 미해결로 둡니다
│   └ …                      │
└────────────────────────────┴────────────────────────────────────
```

- **목적:** 변경이 어디에 영향을 줄 수 있는지 근거 종류별로 본다.
- **콘텐츠:** 근거 종류 탭 세 개. 정적 참조는 parser가 읽은 구문. 함께 바뀐 이력은 서버 이력 통계이며 로컬 HEAD가 서버 스냅샷과 같고 원격 연결이 있을 때만 활성화. AI 추정은 별도 탭.
- **보조 정보:** 선택 항목의 위치·근거 상세.
- **버튼:** `분석`(읽기), 과거 이력 탭의 `서버 연결하기`.
- **표시 방식:** 탭마다 배지가 다르다(`정적`, `통계`, `AI`). 공동 변경 탭에는 "원인이 아닌 통계입니다" 한 줄을 고정 표시.
- **오류/빈 상태:** 연결이 없으면 "서버 연결 안 됨 — 과거 이력은 표시할 수 없습니다. 0건이라는 뜻이 아닙니다." HEAD가 서버 스냅샷과 다르면 "서버 분석이 이 커밋과 맞지 않습니다".

### S9. 알림 (전역)

```text
┌ 알림 (읽지 않음 3)               [ 모두 읽음 ]  [ 새로고침 ]
│ 프로젝트 [전체▾] 종류 [전체▾] 심각도 [전체▾] [안 읽음만]
├─────────────────────────────┬───────────────────────────────────
│ ● 오류  테스트 실패 · my-repo │ 선택한 알림 요약
│ ● 주의  AI 점검 완료(3건)     │  [ 해당 화면으로 이동 ]
│   정보  제안 #2 적용됨         │  ⓘ 이동만 합니다. 실행·수정·전송 없음
└─────────────────────────────┴───────────────────────────────────
```

- **목적:** 모든 프로젝트의 결과를 한곳에서 확인하고 해당 위치로 이동한다.
- **상단:** 읽지 않음 수 + `모두 읽음`.
- **콘텐츠:** 목록 + 요약 2분할, 필터는 칩/드롭다운. 필터는 현재와 같은 네 가지(프로젝트·종류·심각도·읽음).
- **버튼:** `해당 화면으로 이동`(읽기). 알림 자체에는 실행 버튼을 두지 않는다.
- **표시 방식:** 심각도는 색+아이콘+문자.
- **상세 연결:** 알림 → 해당 프로젝트 탭의 해당 기록(S4~S6), 서버 분석 알림 → 웹 분석 화면.
- **오류:** 대상이 삭제·만료됐거나 프로젝트가 목록에 없으면 이유를 사람말로 안내(현재 `navigation.js`에 있는 분기).
- **빈 상태:** "알림이 없습니다."

### S10. 계정·연결

```text
┌ 계정·연결
├ 계정      로그인 안 됨 (선택 사항)            [ 브라우저로 로그인 ]
│           ⓘ 로그인하면 서버 분석과 과거 이력을 쓸 수 있습니다
├ 로그인 진행 중
│           앱 확인 코드  K7-4Q9    브라우저에서 같은 코드를 입력하세요 (5분)
├ 프로젝트 연결 (최대 16개)
│  my-repo   →  [ 서버 저장소 선택 ▾ ]      [ 계정·저장소 확인 후 연결 ]
│  ▸ 고급: 저장소 ID 직접 입력
└ 로그아웃 (세션 폐기)  ▸
```

- **목적:** 선택 기능인 서버 연결을 관리한다.
- **콘텐츠:** 계정 카드, 로그인 진행 카드, 프로젝트 연결 표.
- **버튼:** `브라우저로 로그인`(외부 브라우저 열기), `계정·저장소 확인 후 연결`, `연결 상태 확인`, `로그아웃`.
- **입력:** 서버 저장소를 숫자 ID 입력 대신 목록에서 선택하게 하고, 숫자 입력은 "고급"으로 내린다.
- **로딩:** 로그인 대기 중에는 확인 코드를 크게, 남은 시간과 `취소`를 보여 준다(흐름은 5분 유효).
- **오류:** 네트워크, 인증서, 승인 거절, 만료를 구분해 안내(현재는 "요청을 완료하지 못했습니다" 하나뿐). 한도 16개 도달은 "새 연결을 보류했습니다. 기존 기록은 보존됩니다."
- **빈 상태:** 프로젝트가 없으면 "먼저 프로젝트를 등록하세요."

### S11. 설정

- 섹션: 에디터(VS Code/Cursor, 실행 파일 선택), AI(기본 모델, 로컬 모델 상태 확인, API 키는 점검 때마다 입력하고 저장하지 않는다는 안내), 프로젝트 기본값(최근 커밋 수), 진단(`최소 진단 정보 저장`, 업데이트 상태 읽기 전용), 모양(테마).
- 좌측에 설정 하위 목록, 우측에 항목. 저장은 즉시 적용하거나 항목별 `저장`.
- 로컬 모델이 감지되지 않으면 "Ollama를 찾지 못했습니다. 모델 설치는 자동으로 하지 않습니다."

### 근거 종류 배지

| 배지 | 의미 | 모양 |
| --- | --- | --- |
| 실측 | 실제로 실행해서 얻은 결과 | 실선 테두리 + ✔ |
| 정적 | parser가 읽은 구문 | 실선 테두리 + 구조 아이콘 |
| 통계 | 서버 이력의 공동 변경 | 실선 테두리 + 그래프 아이콘 |

점선은 "아직 검증되지 않았다"는 뜻으로 일관되게 쓴다.

### 승인 패널 (S4 ③, S5, S6 공통)

1. 앱 안 화면이 "무엇이 일어나는지"를 문장으로 보여 준다.
2. 사용자가 `승인…`을 누른다.
3. OS 네이티브 확인창이 최종 확인한다.
4. 결과를 기록에 남기고 알림에 연결한다.

### 상태 3종 규칙

로딩은 영역 단위 스켈레톤으로 하고 전체를 막지 않는다. 오류는 원인(사람말) → 다음 행동 버튼 → 접힌 오류 코드 순서. 빈 상태는 이유 → 다음 행동 한 가지.

## 6. 시각적 방향

**콘셉트: "정밀 계기판".** 에디터·Git 클라이언트와 같은 계열의 밀도 높은 개발자 도구 톤. 장식 없이 상태와 근거가 시각 위계를 만든다.

- **색:** 기존 `tokens.css` 토큰(중립 청회색 + 단일 파랑 강조)을 그대로 쓰고 새 색을 추가하지 않는다. 의미 색(성공/주의/오류)은 상태 표시에만 쓴다. 라이트·다크는 이미 있다.
- **밀도:** 기본 글자 13px, 표 행 높이 32px, 4px 격자. 큰 카드와 넓은 여백 대신 패널을 1px 경계선으로 나누고 카드 안에 카드를 넣지 않는다. 그림자는 메뉴·대화상자에만.
- **글꼴:** UI는 Segoe UI / Malgun Gothic, SHA·경로·명령·로그는 Cascadia Mono(둘 다 토큰에 이미 있음).
- **정보 표현:** diff는 색만이 아니라 `+`/`−` 기호도 함께. 상태는 색+아이콘+문자를 같이 써서 색각 이상이나 고대비 모드에서도 구분된다.
- **아이콘:** 현재의 문자 기호(▣ ⚙ ·) 대신 16px 단선 아이콘 한 벌로 통일. 이모지나 일러스트는 쓰지 않는다.
- **모션:** 패널 열고 닫기 외에는 없으며 `prefers-reduced-motion`을 따른다.
- **피하는 것:** 그라데이션, 큰 일러스트, 온보딩 투어 팝업, 상태 없는 장식 카드.

## 8. 가정과 확인이 필요한 것

- **서버 저장소 목록 호출:** S10의 "목록에서 선택"은 저장소 목록 API를 전제로 한다. 스테이징 VM에서 `GET /repositories?limit=200`이 422를 낸 적이 있으나 아직 조사하지 못했다. 이 호출이 정상이 아니면 숫자 ID 입력을 기본으로 유지해야 한다.
- **"지금 할 일" 규칙, 활동 목록, 마지막 점검 시각:** 에이전트 API가 이런 요약 데이터를 이미 주는지 확인하지 못했다. 없으면 화면 쪽에서 합치거나 항목을 줄여야 한다.
- **작업표시줄 배지·점프 목록:** 후보일 뿐 가능 여부를 확인하지 않았다.
- **탭 구조로 바꾸면 달라지는 것:** 현재 알림은 "이동만 하고 스크롤"하는 방식이므로, 탭 전환 후 해당 기록을 열도록 `navigation.js` 동작을 맞춰야 한다.
- **접근성:** 키보드 순서, 스크린리더 발화, 고대비는 설계 의도일 뿐 검증하지 않았다.
- **목업:** 샘플 데이터로 동작을 흉내 낸 것이며 실제 에이전트·서버와 연결되지 않는다.

## 9. 결정이 필요한 것

1. 용어 변경안(1장)의 채택 여부. 핵심은 "고정 입력 → 점검 대상(변경 스냅샷)".
2. AI 점검을 4단계 스텝으로 나눌지, 한 화면에 두고 접을지. 단계형은 초보자에게 쉽지만 반복 사용자는 클릭이 늘어난다.
3. 구현 범위와 순서. 구현은 별도 승인 후 진행한다.

## 10. 구현 상태 (2026-10-30 기준, 실제 코드·실행 결과 기준)

목업에 맞춰 `frontend/pages/workspace.html`을 뷰·탭 구조로 바꿨다. 상세 변경 목록은 변경 이력과 보고서를 따른다.

**구현됨**
- 레일 뷰 4개(프로젝트·알림·계정·설정)와 첫 실행 안내, 프로젝트 목록.
- 프로젝트 헤더(고정): 선택기, 브랜치·변경·충돌 칩, 탭 7개(개요·변경·AI 점검·개선 제안·테스트·린트·전후 비교·영향 범위).
- "지금 할 일" 카드(실제 Git 상태에서 규칙 판정), 창 제목 갱신.
- AI 점검 4단계 스텝(스냅샷·미리보기 조건에 따른 단계 제한, 클라우드·재실행 필드의 조건부 표시).
- 위험 라벨(읽기·전송·파일 변경·명령 실행), 영향 범위 근거 배지(AI 추정은 점선).
- 명령 팔레트(Ctrl+K), Ctrl+O, Ctrl+1~7, 탭 방향키, 600×400 최소 창 대응.

**설계와 다르거나 아직 연결되지 않음**
- 네이티브 메뉴 막대, 보조 정보(인스펙터) 패널, 폴더 끌어다 놓기 등록.
- 서버 저장소 목록에서 선택(8장의 `GET /repositories?limit=200` 422 미조사). 숫자 ID 입력 유지.
- 프로젝트 표의 브랜치·변경 열, "마지막 점검" 시각, Ollama 상태 확인.
- 작업표시줄 배지·점프 목록.
- 스크립트가 그리는 동적 문구 일부는 옛 용어가 남아 있다(기존 테스트 호환을 위해 유지).
- 근거 배지는 문구 접두어를 기준으로 붙이므로, 에이전트가 구조화된 근거 종류를 주면 교체해야 한다.
- 스텝에서 개선 제안(`workspace-refactor-preview`)으로 이어지는 경로는 단계에 넣지 않았다.
