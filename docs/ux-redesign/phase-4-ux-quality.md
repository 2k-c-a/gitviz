# Phase 4 — 전체 UX/UI 품질 검증과 최종 개선 보고

검증일: 2026-10-29 (Asia/Seoul). 기준은 c459f29 이후 이 작업 디렉터리에 구현한 Phase 1~3이다. 설치되어 있던 이전 패키지를 최신 소스로 간주하지 않았다.

**결과:** 검증 범위에서 P1 2건과 P2 10건을 수정했다. P0는 발견하지 않았다. Phase 4의 렌더러 검사 42/42, 기존 데스크톱 단위 테스트 48/48, AI 모듈 테스트 39/39가 통과했다. 이는 실서비스 GitHub 수집·모델 추론의 성공이나 배포 승인 판정이 아니다.

## 1. 최종 앱 구조와 설계 대비

사전 확인: [프로젝트 진단](phase-1-c459f29/project-audit.md), [UX 문제](phase-1-c459f29/ux-problems.md), [정보 구조](phase-1-c459f29/information-architecture.md), [와이어프레임](phase-1-c459f29/wireframes.md), [구현 계획](phase-1-c459f29/implementation-plan.md), [공통 기반](phase-2-common-ui.md), [핵심 화면 구현](phase-3-core-screens.md), desktop 실행·빌드 설정과 실제 UI/API 코드를 검토했다.

구조는 Electron의 Windows native 창, sandbox renderer와 기존 Vanilla JS/HTML/CSS·Chart.js·D3를 유지한다. 로컬 workspace와 원격 분석 UI의 IPC 권한 경계도 유지했다. 분석식·DB 모델·서버 API·라이브러리·설치 의존성은 변경하지 않았다.

```text
전역: 저장소 탐색 / 최근·내 분석 / URL 분석 시작 / 설정 / 로컬 워크스페이스
저장소: 분석 개요 / 개발 활동 / 협업 네트워크 / 파일 분석 / 분석 이력 / AI 리뷰
공통: repo·snapshot·기간 표시, 테마, 기여자·파일 상세와 내부 뒤로 가기
```

| 설계와 실제의 차이 | 이번 판단/처리 |
| --- | --- |
| 탐색·최근 목록을 한 화면 탭으로 묶는 설계 → 실제는 기존 별도 주소 | 기존 라우팅을 유지했다. 이 단계에서 다시 통합하지 않았다 |
| 전체 창 크기만으로 본문 열 수 결정 | 상세 패널을 열면 본문 폭이 줄어 실제 가로 넘침 발생. 본문의 가용 폭을 기준으로 개요·KPI·트리 열 수가 바뀌도록 수정 |
| 풍부한 설정 하위 탭 설계 → 현재는 원격 AI 제공자·모델·키 관리 | 기존 기능 범위를 명시했다. 테마는 상단, 로컬 도구는 별도 workspace에 유지 |
| 최근 변경 파일의 날짜순 이력 | API에 마지막 수정 시각이 없어 관측 구간 변경 빈도로 제공. 최신 날짜순이라고 표시하지 않음 |
| 리뷰 심각도 표시 제안 | 실제 응답의 priority는 검토 순서다. 장애 등급으로 바꾸지 않음 |
| 상세 폭 조절·전역 방문 이력 조작 제안 | 현재는 반응형 상세 폭과 내부 stack/닫기로 복귀. 드래그 폭 조절·새 전역 뒤로 버튼은 추가하지 않음 |

내비게이션은 넓은 창에서 208px, 중간 크기에서 56px rail, 720px 미만에서 overlay를 유지한다. native 최소 창 크기 600×400을 올려 문제를 숨기지 않았다.

## 4. 사용자 흐름별 테스트 결과

검증용 API는 실제 frontend의 transport/typed IPC를 통과한다. DOM을 흉내 낸 모형이 아니라 실제 Electron 렌더러를 실행했다. 테스트 데이터는 `desktop/tests`에만 있으며 제품의 API 데이터나 분석 결과를 대체하지 않는다.

| 흐름 | 실행한 범위 | 결과/실제 서비스 한계 |
| --- | --- | --- |
| A 레포 분석 | Electron/agent 기동 기반, 검색·결과·선택·명시 POST·상태 조회·완료 snapshot 개요. 실패·재시도 안내·마지막 성공 결과 복구 | UI 통과. 실제 GitHub OAuth/수집 worker는 미실행 |
| B 기여자 | 개요/활동→기여자→주요 파일→상세 뒤로/닫기→분석 화면 | 통과. 늦은 상세 응답 경쟁·포커스 복귀는 기존 renderer 테스트도 통과 |
| C 협업 | 그래프 진입·선택/강조·확대·필터·200명 이름 검색·상위 협업 쌍→기여자→수정 파일 | 통과. 실제 조직의 고밀도 분포와는 다른 합성 부하 데이터 |
| D 파일 | 빈도 상위/목록→파일→수정 기여자→뒤로→공동 변경 파일→이전 파일/부모 복귀. 1,000파일에서 50행·검색·긴 경로·3회와 방향별 분모 | 통과. 날짜순 ‘최근 수정 파일’ 검사는 API 미지원 |

| F 설정 | 저장·교체·삭제, 빈 입력 안내·잘못된 키 거절·원문 비노출, 누락 키 실행 차단, 사용량 지연 시 입력 보존 | UI 통과. 제공자의 실제 key 유효성 확인은 미실행 |

창 변경 시 Chart ResizeObserver의 안정화를 기다린 뒤 검사했다. resize 이벤트 직후의 과거 canvas 폭을 영구 오버플로로 오판하지 않도록 했으며, 실제 본문 overflow를 숨기는 CSS로 통과시키지 않았다. 파일 표의 내부 가로 스크롤은 의도된 탐색이고 main 전체 가로 스크롤은 방지했다.

키보드 검증은 PR 방향키/선택 탭/tabpanel, 네트워크 이름 검색과 native 목록 포커스, 기존 테스트의 Enter/Space action·모달 Tab/Escape·포커스 복귀·상세 responsive 전환을 포함한다. 색 외에도 노드/목록 이름·클러스터 텍스트, 수치·범례·상태 문구를 제공한다. 다크 축 제목·badge 크기·실제 막대 색상을 검사했다. 전체 WCAG 적합성이나 실제 스크린리더 발화 인증은 수행하지 않았다.

성능/안정성: 1,000파일의 DOM을 50행으로 제한하고 페이지·검색이 동작함을 확인했다. 200노드·600연결 렌더링·배치 정지·검색을 실행했다. 같은 cursor에 대한 동시 요청 2회→1회를 확인했다. 기존 snapshot 요청 합치기, 실패 cache 제거, 계정 변경 cache 무효화, 상세 응답 세대 폐기, poller stop/abort·backoff 검증을 유지했다. 실제 대형 저장소의 최대 지연·FPS·메모리 상한을 계측한 성능 보장은 아니며 가상 스크롤/상태 관리 라이브러리 등은 추가하지 않았다.

## 7. 미해결·배포/시연 전 확인

다음은 미검증 또는 기존 데이터/계약 제약이다. 자동화 통과로 닫지 않았다.

1. **실서비스 E2E:** 배포 origin 설정·실제 OAuth·비공개 저장소 권한, GitHub 한도, Postgres/Redis/Celery 수집, 실제 키 확인·유료 제공자/설치 모델 추론과 비용을 별도 계정·환경에서 검증해야 한다. 현재 실행 프로세스에서 `GITVIZ_SERVER_ORIGIN`이 설정되지 않았음을 확인했다(값·비밀 정보는 출력하지 않음). 따라서 운영 서버·실제 세션을 연결한 검증은 실행하지 못했으며, 이번 API 실패/성공은 제어된 응답이다.
2. **설치 앱:** 기존 설치 EXE를 이 변경의 산출물로 사용하지 말고 최신 소스로 패키지를 다시 만든 뒤 설치/재시작·창 상태·서명·업데이트 정책을 검증해야 한다. 패키지 생성·배포는 이번에 실행하지 않았다.
3. **Windows 환경:** 125/150/200% DPI, 다중 모니터, 고대비, 실제 GPU/드라이버, Narrator/NVDA의 발화·탐색, native 제목줄을 포함한 실제 조작은 별도 확인해야 한다.
4. **실제 데이터 규모:** 최대 크기 GitHub 이력과 실제 고밀도 조직 그래프·수천 지적의 CPU/메모리/FPS·읽기 경험은 별도 계측해야 한다. 이번 합성 1,000파일/200노드/40개 장문 지적을 그 결과로 일반화하지 않는다.
5. **조회 계약:** 검색의 오래된 타인 저장소 ID 매핑, 날짜순 파일 변경 이력은 기존 API 제약이 남는다. 상위 기여자/공동 변경/상세 후보 및 불러온 AI 지적 범위도 기존 제한을 따른다. 가짜 데이터로 빈 부분을 채우지 않았다.
6. **설계 보류:** 검색/최근 통합 탭, 상세 폭 수동 조절, 전역 방문 이력 버튼, 풍부한 설정 탭은 향후 별도 범위로 판단한다. 현재 주요 상세 왕복은 검증했다.
