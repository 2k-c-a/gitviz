# GitViz 로컬 모델 지원 범위

## 결정 및 현재 상태

- 지원할 구성은 **GitViz 백엔드·AI worker와 모델 런타임을 같은 PC에서 실행**하는 방식이다. 브라우저의 실행 위치가 아니라 모델을 호출하는 worker의 위치가 기준이다.
- 웹 GitViz가 각 사용자의 다른 PC에 설치된 모델을 연결하는 기능은 **후속 과제**로 남긴다.
- 현재 Anthropic·OpenAI·Gemini BYOK와 같은 PC의 Ollama adapter·설정·화면을 구현했다. 실행 설정과 검증 한계는 [제공자 지원 안내](AI_PROVIDER_SUPPORT.md)에 정리했다. 실제 설치 모델의 smoke·품질 검증은 아직 남아 있다.
- 첫 로컬 런타임은 Ollama다. 관리자가 설치 모델 이름과 전체 digest를 지정한다. 기본 후보 qwen2.5-coder:7b의 실제 품질·속도는 별도 smoke로 확인한다.

## 같은 PC에서의 실행 흐름

```text
브라우저 → 같은 PC의 GitViz API → 기존 작업 큐 → 같은 PC의 AI worker
                                                   ↓
                                          로컬 모델 API
                                                   ↓
                                기존 출력 검증 → 결과 저장 → 화면
```

사용자는 로컬 실행을 선택하고 설치된 모델, 고정 SHA, 분석할 코드 범위를 확인한 뒤 작업을 시작한다. GitHub PR 수집·입력 준비·작업 취소·결과·피드백은 기존 흐름을 재사용한다.

로컬 추론용 코드와 프롬프트는 같은 PC의 모델 런타임에 전달된다. GitHub 인증·PR 수집과 모델 다운로드에는 인터넷이 필요할 수 있으므로 제품 전체가 오프라인으로 동작한다고 표시하지 않는다.

## 구현 범위

| 영역 | 필요한 변경 |
|---|---|
| Provider | 로컬 adapter와 provider 등록. 로컬 실행을 실제 외부 제공자로 자동 대체하지 않는다. |
| 설정·연결 | 운영용 로컬 endpoint, 연결 확인, 설치된 모델 조회. `AI_TEST_PROVIDER_BASE_URL`은 시험용으로 유지하며 로컬 기능 설정으로 사용하지 않는다. |
| 모델 고정 | 모델 식별자·버전 또는 digest, context 한도, 출력 한도와 프롬프트 버전을 작업에 고정한다. |
| 인증·동의 | API key 없는 provider를 지원한다. 외부 제공자 전송 동의와 로컬 실행 확인을 구분하되 로그인·입력 소유자·저장소 권한 검사는 유지한다. |
| 비용·사용량 | 로컬은 제공자 API 과금 대상이 아님을 표시한다. 실행 횟수·토큰·시간·동시 실행 제한은 관리하고, 외부 제공자용 USD 예약·정산 정책과 구분한다. |
| 화면 | 로컬/외부 실행 선택, 모델 목록·연결 상태·한도·실행 위치를 표시한다. 로컬 선택에는 BYOK 키 입력을 요구하지 않는다. |
| 실패·보관 | 모델 미설치·연결 실패·메모리 부족·시간 초과·프로세스 종료·취소를 처리한다. 원문 암호화·보관·삭제 정책은 유지한다. |
| 출력 | summary/review schema와 파일·side·줄·인용 검증을 유지한다. 로컬 출력도 사람 검증 전 상태로 저장한다. |

GitViz를 컨테이너로 실행할 경우 worker 안의 `localhost`는 모델이 실행되는 PC의 호스트와 다르다. 이번 버전은 호스트 worker와 호스트 Ollama의 loopback 연결만 지원한다. 컨테이너의 host.docker.internal 연결은 허용하지 않으며 별도 과제로 남긴다. 브라우저가 모델 API를 직접 호출하는 방식은 이번 범위에 넣지 않는다.

## 구현 및 검증 순서

1. provider·실행 위치·키 선택·동의·과금 방식의 계약과 DB 제약 변경을 정리한다.
2. 로컬 adapter, 연결 확인, 모델 목록과 고정 profile을 구현한다.
3. 기존 생성 서비스와 작업 큐에 연결하고 로컬 실행의 한도·실패·취소 처리를 검증한다.
4. 화면의 Anthropic 하드코딩을 provider 선택 방식으로 바꾸고 로컬 모델 선택을 연결한다.
5. 같은 PC에서 연결·토큰 한도·summary/review·검증 실패·중단·취소·복구·원문 삭제 smoke를 수행한다.
6. 지원 모델별 사람 정답 평가를 수행한다. Anthropic 평가 결과를 로컬 모델의 품질 근거로 사용하지 않는다.

완료 조건은 같은 PC에서의 입력 준비부터 결과·피드백까지 실제 실행, 외부 모델로의 무단 전환 방지, 기존 Anthropic 경로의 회귀 통과, 모델별 품질·자원 한계 기록이다. 현재 Anthropic MVP의 실제 smoke·품질 평가·운영 스냅샷 미확인 상태는 별도로 유지한다.

## 후속 과제: 웹 GitViz와 사용자 PC 연결

별도 단계에서 다음을 설계한다. 이번 로컬 지원에는 포함하지 않는다.

- 사용자 PC 연결 도우미 배포와 업데이트
- 계정과 기기 연결·인증·해제
- 원격 작업 배정·코드 전달·결과 제출과 기기별 접근 제한
- PC 절전·종료·연결 끊김, 중복 제출과 작업 복구
- 코드가 서버·사용자 PC 사이를 이동하는 범위에 대한 동의와 보관 정책

참고: [Ollama 로컬 API](https://docs.ollama.com/api/introduction), [Ollama 로컬 실행·네트워크 설정](https://docs.ollama.com/faq).
